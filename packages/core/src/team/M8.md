# M8 device carrier and mobile integration

Issue #4146 adds application-defined Consumers of the existing Team service and DSH API Gateway. SQLite `member_grants` remains the durable authority. Migration 142 adds `kind` (`browser-session` or `paired-device`), `device_name` and the optional Noise `public_key`. Device IDs are grant IDs, and the credential is `member.<random-token>`; only its SHA-256 digest is stored. M3 device management must list/revoke those grants. This migration must be reconciled with another slice if it also allocates generation 142.

The Device Gateway recognizes the member credential before its Owner proxy. Unary calls invoke the Gateway with that grant's member Peer; mux opens use `wireStream.open` with the same Peer and remote-access policy. No member operation calls the Owner cookie mint/proxy. Suspension, reset, mode off and revocation retain M1's grant and Peer invalidation. Password changes preserve the caller's grant while retiring other initial-password grants. Native DSH business methods remain denied. Owner-paired devices retain their original path.

Invitations carry identity, username, expiry and HTTPS addresses only. Passwords travel separately. Public Connect addresses use pinned Noise; ordinary Host HTTPS uses certificate-validated requests after fingerprint discovery. A private relay that additionally requires an admission token is excluded from invitations because an invitation cannot contain that token. Encrypted LAN invitation discovery is not introduced here. Member self-pairing uses the existing ten-minute, single-use offer lifecycle; redeeming its QR creates a device grant for the offer's Human. The offer itself authorizes the redeeming Noise key and does not require an Owner approval.

## Mobile screen contract

All functions below live under `apps/mobile/src/host/`. They return codes, without UI copy.

- `team-invitation.ts`: `parseTeamInvitation(link, now?) -> TeamResult<TeamInvitation, InvitationError>`. `TeamInvitation` is `{ v: 1, host: { id, name, fingerprint }, routes, username, expiresAt }`. Parsing normalizes member-entry URLs to origins and strips unrecognized fields.
- `team-client.ts`: `signInTeamDevice({ carrier, invitation, password, deviceName, route?, signal?, now? }) -> Promise<TeamResult<SavedHost>>`. It discovers and checks the Host identity before sending a password. `route`, when provided, must be in the parsed invitation. Without it, unreachable routes fall through to the next invited route within a shared thirty-second deadline; a credential or fingerprint refusal never retries another Host. It creates a phone Noise key and returns a secure-store-ready identity. Obtain the carrier with `nativeCarrier()`; screens do not call fetch.
- `team-client.ts`: `changeTeamDevicePassword({ carrier, host, current, next, signal? }) -> Promise<TeamResult<SavedHost>>`. The input Host remains gated on failure. Success returns a new Host with `member.mustChangePassword: false`; persist it through `hostSession.pairMember` before entering the normal Client.
- A received member self-pairing QR can use the existing `parsePairingLink` and `redeemPairing` functions in `pairing.ts` to obtain its pending `SavedHost`, then `hostSession.pairMember` for confirmation and persistence. Its `member: true` payload forces a new member grant instead of treating a scan as an existing pairing route update.
- `team-client.ts`: `memberPairingOffer(client) -> Promise<TeamResult<MemberPairingOffer>>`, where `MemberPairingOffer` is `{ link, qr: { size, path }, expiresAt, receipt }`. The Host derives the caller's Human; no target Human is accepted.
- `member-identity.ts`: `prepareMemberIdentity(savedHosts, host, confirmed?)` returns either the prepared Host or `identity-switch-required` / `fingerprint-mismatch`. `identitySwitchRequired(previous, next)` compares Human IDs for the same stored Host.
- `host-session.ts`: `hostSession.pairMember(host, { confirmedIdentitySwitch? }) -> Promise<TeamResult<SavedHost>>`. Call once to persist a sign-in or password-change result. On `identity-switch-required`, retain the pending Host in memory, ask for confirmation, and retry with `confirmedIdentitySwitch: true`. Cancel by discarding that pending result. Confirmation never bypasses fingerprint pinning. The serialized mutation clears the previous identity's conversations, drafts, media and presentation state before replacement. Password-gated Hosts remain stored, but their normal Host Clients are not started.
- `member-identity.ts`: `memberPasswordGate(savedHost)` returns `{ kind: 'loading' }` before hydration, `{ kind: 'signed-out' }`, `{ kind: 'owner' }`, or `{ kind: 'password-change-required' | 'ready', host, member }`. Wait for Host-session hydration before choosing a screen.
- `SavedHost.member?: HostMemberIdentity` is `{ humanId, displayName, username, fingerprint, mustChangePassword }`. Self-pairing can have an empty username; use `displayName` for the Host row. The existing SecureStore document remains keyed by `hostId`, preserves several Hosts and restores one identity per Host. `loadSavedHosts` / `saveHosts` remain the storage adapters; screens use the Host session so runtime state follows persistence.

`TeamResult<T>` is `{ ok: true, value: T } | { ok: false, code: TeamErrorCode, retryAfterSeconds?: number }`.

`InvitationError`: `invitation-invalid`, `invitation-expired`, `invitation-version-unsupported`.

`TeamErrorCode` additionally includes `credentials-invalid`, `rate-limited`, `insecure-transport`, `team-mode-off`, `member-suspended`, `fingerprint-mismatch`, `password-change-required`, `password-weak`, `password-reused`, `invalid-input`, `unreachable`, `response-invalid`, `request-cancelled`, `identity-switch-required`, `storage-failed`, `remote-access/denied`. Screens own all translations, labels and confirmation copy. No native package or configuration changes are required.

## Performance and verification boundary

Password hashing retains M1's two workers, sixteen waiting operations and username/socket rate limits. Grant admission uses indexed lookups and throttles last-seen writes to once per minute; the regression repeats admission without new writes. The member mux permits 64 sockets, 16 logical streams per socket and 256 logical streams per Host, with 1 MiB incoming frames and 4 MiB outgoing backpressure. Peer disposal and Plugin unload close sockets and cancel streams. No polling timer or dependency was added to the mobile idle path.

A task-local real Host check compared one existing browser sign-in with one Noise device sign-in, then changed the initial password and confirmed a native business API refusal. Its timings are latency observations under local load, not a speedup claim. The Node integration also covers member-owned and forbidden Channel unary/stream dispatch, every sign-in refusal, forced-password failures, grant revocation, and self-pairing single use/expiry. Native iOS, Android and Human acceptance remain separate from Host and module verification. Claude owns the screens, visible copy, bilingual release fragment and device QA.
