# Team mode M1 runtime boundaries

This is the application-defined implementation of the M1 wire contract in #4140, under the accepted target design in ADR-0336 and spec #4137. It does not qualify the later private Bot, role, Workspace or offboarding slices.

`TeamService` owns canonical SQLite identities (`humans`), credentials (`member_credentials`), grants (`member_grants`) and the Team settings singleton. The Owner retains `local-human`. Existing paired devices acquire that Human ID without changing their credential. Public visibility is an indexed-column-sized addition to group Channel records; membership stays in `channel_human_members`.

`TeamService` creates one process-local DSH Peer per live member grant. A SHA-256 token digest is persisted; the cookie token never enters the Peer principal or database. The principal contains only `kind`, `humanId` and `grantId`. Every Gateway policy decision and bridge invocation checks current grant, mode and member status. Revocation, suspension and mode changes invalidate DSH access snapshots; revocation and suspension dispose the affected Peers. Mode off revokes every grant, disposes member Peers and leaves the Owner unchanged. Account status is retained while the mode switch prevents admission, so previously active members can sign in freshly after re-enabling.

The Device Gateway's `/botharness-device/team/` entry serves the shared Client sign-in renderer before admission. Cookie admission is separate from the existing paired-Owner device proxy. The member shell reads DSH's existing index with `webServer.readResource(request, peer)`, as upstream Liveshare does. DSH renders its access baseline for that Peer through `webserver/index-inject`. The upstream `viewerCarrierScript` installs `__DSH_TRANSPORT__` before shell boot. Its unary and bounded stream-poll operations are handled locally through `typertGateway.invoke` and `wireStream.open` with the same member Peer. Static bundles use `clientModules.fetchBundle`; no member operation obtains, forwards or mints an Owner cookie. Stream state is bounded per grant and Host, expires after two minutes without polling and is released on Peer disposal or Plugin unload.

The explicit member policy permits Team status/password change/public browse and join, own Channel listing, a blank Bot roster for M1, and membership-checked Channel reads, sends, receipts and streams. The Owner roster and private Channels are never returned to a member. Every DSH-native business endpoint is denied by default. DSH's own access-snapshot subscription is infrastructure allowed by the native access service. Member Activity and private Bots remain deferred to M2. Channel sends while Team mode is enabled carry the speaking Human ID and display name in the message author as well as the M0 Source Event Human ID. Clients must use that author identity; a legacy author without a Human ID denotes the Owner.

The `public` wire field for `channelPublicSet` is mapped to the Host's `publicValue` parameter with a Typert lookup registration. JavaScript class parameters cannot be named `public`; the explicit wire alias preserves the binding contract. All ten Team methods use the existing BotHarness Typert service. Local CLI member evaluation uses an Owner-only Connection Fetch route, which creates and finally revokes a temporary member grant; it dispatches through the same Gateway policy. Unsupported member carriers refuse before sending their operation.

Password hashing uses the already-approved `@noble/hashes` Argon2id implementation: version 19, 19,456 KiB, two passes, one lane, a 16-byte random salt and a 32-byte result. Parameters are stored with every hash and history entry. Unknown usernames perform the same derivation and constant-time digest comparison as wrong passwords. Worker threads keep hashing off the Host event loop; two workers and sixteen waiting operations bound CPU and memory demand. Sign-in buckets are bounded, keyed separately by username and socket IP, and expire after a minute. Client-supplied forwarding headers do not affect the transport or rate-limit decisions.

Performance guard: password work has fixed parameters and bounded concurrency; member authorization uses an indexed grant lookup and a membership lookup by Channel/Human primary key. Public Channel browsing uses one indexed SQL read, and its regression checks the read count. Grant last-seen writes are throttled to once per minute, including asset and stream polling. Existing Owner Channel-list behavior is retained; member listing filters before materializing summaries. Focused tests cover authorization, password failures, public joins, Source Event authorship and CLI file/dispatch behavior. Rendered Client and real Host acceptance are separate gates.
