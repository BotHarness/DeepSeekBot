# M10 Host and CLI logic

Issue #4148 implements application-defined Team Service policy and a Human dimension in the existing usage projection. This is the logic half; Client UI and native/Human acceptance remain separate.

`usageByMember { period }` accepts `today`, `week`, `month`, or `quarter`. It requires `usage.view` in the Service and returns `{ period, start, end, timezone, members, legacy }`. Each member contains `{ humanId, displayName, deleted?: true, totals, bots }`; each Bot contains `{ slug, displayName, totals }`. Buckets use `UsageOverviewBuckets`, including nullable unknown buckets and `partial`. The aggregate uses the same SQL expressions and day boundaries as `overviewUsage`. Member `overviewUsage` scopes the entire query, including totals and pagination, to owned Bots.

Trusted Source Events supply the Human at root-turn admission. `usage_turn_humans` retains that association when DSH commits `turn/start`; receipt fingerprints retain replay deduplication. Assignment creation retains its initiating Human; descendants use the root. Schedules retain their creating Human when supplied by the bridge; idle compaction records the Bot owner. Missing attribution falls back to the Bot owner, then the current Host Owner. Legacy daily rows retain all buckets and receive `legacy = 1`; their reporting identity is the Owner at migration. A requested period reports `legacy: true` only when it contains such rows. No token history is reconstructed from guesses.

`roleUpdate { roleId, models }` accepts `{ kind: 'all' }` or `{ kind: 'only', routes: ['provider/model'] }`. Empty `routes` denies all models. Existing/new Roles default to all; Admin remains all. `modelsAllowed {}` and `teamMode.viewer.models` return the caller's Role union, `{ all: true }` or `{ all: false, routes }`. Owner bypasses restrictions. Effort is not restricted.

Bot model plans, Assignment defaults, Assignment Session switches, Tob's Bot plan, Subagent activation, and native pre-step execution check the Bot owner's current policy. Settings remain intact after restriction; `get`/`list` expose `modelAllowed`. Refusals use `model-not-allowed` with `details.route`, or `permission-required` with `details.permission`. The existing Session failure notice carries the refusal; Claude's UI owns localization. Members receive route-only model catalog entries without credential readiness. Sensitive credential and provider administration methods remain outside the import-free member invocation catalog.

CLI: `usage members --period week`, `roles update <roleId> --models all`, `roles update <roleId> --models provider/model,provider/model`, and `models allowed`; each uses the existing local `--as <username>` dispatch.

Migration integration: this M1/M3 baseline ends at 142. Role policy uses 143 and attributed usage uses 144, the highest generation observed in this task. The schema plan requires contiguous generations; M2 and M9 both currently use 143 and inspected M8 uses 142. The later integration must preserve and renumber all parallel migrations; these numbers are not mutually deployable without reconciliation. M2 owns canonical Bot ownership creation and per-member Tob lifecycle; this slice reads its `ownerHumanId` field and falls back for Host/legacy Bots.

Performance: no dependency, timer, or worker was added. Member reporting uses four aggregate/directory reads plus two permission/Owner reads, independent of the number of members; The bridge loads the Bot directory once for display names, for at most seven reads in total. Role union is one indexed membership query including current-Owner admission. Regression coverage bounds query counts and preserves reconciliation rather than using a timing-only gate. Host/CLI runtime evidence, source tests, Client rendering, and native acceptance remain separate claims.
