# M10 Host and CLI logic

Issue #4148 implements application-defined Team Service policy and a Human dimension in the existing usage projection. This is the logic half; Client UI and native/Human acceptance remain separate.

`usageByMember { period }` accepts `today`, `week`, `month`, or `quarter`. It requires `usage.view` in the Service and returns `{ period, start, end, timezone, members, legacy }`. Each member contains `{ humanId, displayName, deleted?: true, totals, bots }`; each Bot contains `{ slug, displayName, totals }`. Buckets use `UsageOverviewBuckets`, including nullable unknown buckets and `partial`. The aggregate uses the same SQL expressions and day boundaries as `overviewUsage`. Member `overviewUsage` scopes the entire query, including totals and pagination, to owned Bots.

Trusted Source Events supply the Human at root-turn admission. `usage_turn_humans` retains that association when DSH commits `turn/start`; receipt fingerprints retain replay deduplication. Assignment creation retains its initiating Human; a later new-turn delivery captures its requester before asynchronous preparation, while steering keeps the running turn. Descendant usage reads its own durable turn binding. The DSH `subagent/start` Cordis Event captures the trusted parent turn for each activation; initial lineage/creation-time attribution also covers delayed child starts. Nested children inherit their direct parent binding. Late completion never consults a newer root turn. Schedules retain their creating Human when supplied by the bridge; idle compaction records the Bot owner. Missing attribution falls back to the Bot owner, then the current Host Owner. Legacy daily rows retain all buckets and receive `legacy = 1`; their reporting identity is the Owner at migration. A requested period reports `legacy: true` only when it contains such rows. No token history is reconstructed from guesses.

`roleCreate { name, permissions, models? }` persists a supplied policy and defaults to all when omitted. Both role creation and update accept the existing CLI `--models` option. `roleUpdate { roleId, models }` accepts `{ kind: 'all' }` or `{ kind: 'only', routes: ['provider/model'] }`. Empty `routes` denies all models. Existing/new Roles default to all; Admin remains all. `modelsAllowed {}` and `teamMode.viewer.models` return the caller's Role union, `{ all: true }` or `{ all: false, routes }`. Owner bypasses restrictions. Effort is not restricted.

Bot model plans, Assignment defaults, Assignment Session switches, Tob's Bot plan, Subagent activation, and native pre-step execution check the Bot owner's current policy. Settings remain intact after restriction; `get`/`list` expose `modelAllowed`. Refusals use `model-not-allowed` with `details.route`, or `permission-required` with `details.permission`. The existing Session failure notice carries the refusal; Claude's UI owns localization. Members receive route-only model catalog entries without credential readiness. Sensitive credential and provider administration methods remain outside the import-free member invocation catalog.

CLI: `usage members --period week`, `roles update <roleId> --models all`, `roles update <roleId> --models provider/model,provider/model`, and `models allowed`; each uses the existing local `--as <username>` dispatch.

Migration integration: M10 is reconciled with the M2/M4/M9/E4 main baseline at generation 147. Role policy uses 148 and attributed usage uses 149, after main generations 143 (private Bots), 144 (Host relationships), 145 (member lifecycle), 146 (Channel access), and 147 (durable relationship revocation). The schema plan remains contiguous. An upgrade test opens a main-generation 147 database and verifies the M10 migration plus restart without changing M2 ownership, Tob identity, M9 status, E4 pending revocation/retry/suppression state or usage buckets. M2 owns canonical Bot ownership creation and per-member Tob lifecycle; this slice reads its `ownerHumanId` field and falls back for Host/legacy Bots.

Performance: no dependency, timer, or worker was added. Activation binding adds bounded indexed reads and one pending attribution write; an attributed receipt still uses one indexed Human lookup. Parent lineage is traversed only to recover a missing descendant binding. Member reporting uses three aggregate/directory reads plus two permission/Owner reads, independent of the number of members; the bridge loads the Bot directory once for display names, for at most seven reads in total including M2 invocation admission. Role union is one indexed membership query including current-Owner admission. Owner `teamMode` reuses its admitted identity to return unrestricted models without another policy read, preserving main's seven-read budget. Regression coverage bounds query counts and preserves reconciliation rather than using a timing-only gate. Host/CLI runtime evidence, source tests, Client rendering, and native acceptance remain separate claims.

M2/M4/M9 interaction checks cover private Bot and sign-in-created Tob turns, a member mention of their own Bot in a public Channel, and historical receipt retention after permanent member purge. Canonical Source Event authorship stays the first attribution choice. A Bot transfer leaves earlier receipts under their original Human and gives new-owner turns (and unrecorded-background fallback) to the current owner. Recorded Schedule/Assignment creators remain recorded creators. Member Overview follows current Bot ownership, including the transferred Bot's retained history; the per-member report preserves who incurred each receipt. Missing Human directory rows are reported as `deleted: true`, without reassigning their costs to the Owner.
