# Team mode M9 lifecycle boundaries

The application-defined `TeamService` owns password, grant and member lifecycle admission for #4147. The existing Typert Service and API Gateway expose the operations; `team/member-methods.ts` remains import-free and is an invocation catalog, never an authorization grant. Every operation checks `members.manage` inside the Service, the caller's current permission ceiling against all target roles (even for inactive targets), Owner protection and self protection. Admin targets require the Owner. Password reset checks again after hashing and removes Owner-issuance provenance when a manager issues the reset.

The baseline is main `1e17b7fc4` (M1 + M3). Main has no Human-owned Bots, shared roots or member Bot wake paths. Those integrations require reconciliation when M2/M6/M7 merge; this slice does not claim that unmerged Bot code is gated. Human-created group Channels now record `ownerHumanId`; existing Human-owned groups backfill to the current Owner. Bot-owned groups keep their existing owner. Transfer changes that Human ownership and ensures the destination is a Channel member, preserving history and the original authors.

The migration is generation 143 on this baseline because `defineSchemaPlan` requires contiguous generations. M2's unmerged work also uses 143, while the inspected M8 PR was still based on 141 and used 142. Rebase must allocate fresh contiguous numbers after those migrations; do not deploy conflicting migration generations. The migration rebuilds the referenced `humans` table through the database owner's staging workflow, expands statuses to `active` / `suspended` / `deactivated`, and adds indexed status lookup, mode restoration records and anonymous deletion markers.

Reset, deactivation and disabling revoke browser grants and use the existing pairing authority to revoke paired devices and close its streams. Peer disposal cancels browser carrier streams. An unavailable pairing authority refuses before a credential/status change when live paired grants exist. Owner grants and Peers remain valid on mode off. Every non-Owner is suspended while mode is off; the first off records whether the member was active or deactivated, and repeated off preserves that record. Re-enabling restores that state without restoring grants. Reactivation revokes stale grants before opening admission. Password changes keep the invocation's current grant and revoke other grants by default. Explicit `signOutOthers: false` preserves others, except during the forced initial change.

`ContentPurge` owns permanent deletion. It issues at most 128 process-local tokens, bound to actor, target and the previewed private-content fingerprint, with five-minute expiry and single-use confirmation. The Team Service independently rechecks current permissions, deactivation, pending transfers and exact username. Content Purge accepts private-source tombstones and a deleted-Human fact together in its durable monotonic ledger. Checkpoint version 3 carries anonymous Human IDs, deletion times and private Channel IDs; it contains neither credentials nor names. Replay removes identity and credential records, member grants, membership, read/attention state and paired-device metadata, clears private Channel metadata and rewrites shared-message authors as `{ kind: 'human', humanId, deleted: true }`. Shared message bodies remain. Older snapshots cannot restore a deleted identity; pre-transfer snapshot ownership falls back to the current Owner. Existing managed-file reference checks preserve shared attachments and apply private-file cleanup. Failed ledger application fails the operational database closed, with replay required before admission.

Private scope currently comprises exclusive DM Channels identified by Human ownership or sole Human membership. Sources placed outside that scope are retained. Main has no production member DM/Bot ownership, so private-content deletion is qualified with canonical-store fixtures; production member Bot deletion and wake suppression remain an M2 integration gate. Browser stream cancellation and paired stream closure use actual DSH Peer/Gateway and actual device pairing in tests. The paired test binds its admission authority to the target Human because M1/M3 has no member self-pairing; this is not M8 mobile sign-in qualification.

## Wire contract for the Client

All payloads use Human IDs. Existing password errors (`credentials-invalid`, `password-weak`, `password-reused`, `password-change-required`, `rate-limited`) remain. Invalid payloads use `invalid-input`. Management refusals are `permission-required` with `details.permission`, `permission-not-grantable` with `details.permission`, `owner-protected` and `member-not-found`. Self and Admin protection use `permission-required` with `details.permission: 'owner'`.

| Method                  | Payload                                      | Success                                                                                               |
| ----------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `memberPasswordReset`   | `{ humanId }`                                | `{ initialPassword }` (one-time reveal)                                                               |
| `memberPasswordChange`  | `{ current, next, signOutOthers?: boolean }` | `null`; default `true`                                                                                |
| `teamMode`              | `{}`                                         | Existing view plus `activeMembers`                                                                    |
| `teamModeSet`           | `{ enabled: boolean }`                       | View plus `suspendedMembers` (count active before off; zero on on/no new active members)              |
| `memberDeactivate`      | `{ humanId }`                                | `null`                                                                                                |
| `memberReactivate`      | `{ humanId }`                                | `null`; mode off: `team-mode-off`                                                                     |
| `memberTransferPreview` | `{ humanId }`                                | `{ channels: [{ channelId, name }], bots: [{ slug, displayName }] }`                                  |
| `memberTransfer`        | `{ humanId, toHumanId }`                     | `null`; missing destination: `member-not-found`; self/inactive destination: `transfer-target-invalid` |
| `memberPurgePreview`    | `{ humanId }`                                | `{ token, counts: { channels, bots, messages, files } }`                                              |
| `memberPurgeConfirm`    | `{ humanId, token, username }`               | `null`                                                                                                |

Both purge methods return `member-active` unless deactivated, and `transfer-required` while group ownership remains. Confirmation returns `purge-token-invalid` for an incorrect username, token, actor, target, changed private scope, expired token or reused token. Content Purge failures retain `purge-unavailable`. Tokens expire on Host restart. Directory status adds `deactivated`; mode suspension remains `suspended`. The UI owns labels, dialogs, password reveal, translations and deleted-author rendering. No Client or mobile code changes belong to this logic branch.

## Performance and verification

No dependency, background worker or timer is added. Argon2 retains the existing bounded queue. `teamMode` adds one indexed active-member count; directory and effective-permission query budgets stay unchanged at 1,003 Humans. Revocation scales with the target's live grants/devices, not all Host content. Purge preview/confirmation is explicit cold-path work; it selects private sources through SQL, fingerprints the selected content and uses existing managed-reference scans and ledger application. Tokens are bounded at 128 and expiration cleanup runs on preview requests. Tests cover these resource bounds and role/refusal semantics independently of timing; no end-to-end performance gain is claimed.
