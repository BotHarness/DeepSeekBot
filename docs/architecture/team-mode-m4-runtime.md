# Team mode M4 runtime boundaries

The application-defined `TeamChannels` Service owns Channel audience, policy and Human DM operations. It uses the existing operational database and the existing BotHarness Typert Service through the API Gateway. The caller Human comes from the authenticated invocation. No member request mints or forwards an Owner cookie. `team/member-methods.ts` remains an import-free admission catalog, not an authority grant.

The migration uses generation **146**, following private Bot ownership (143), reciprocal Host relationships (144) and member offboarding (145). Upgrading a main-generation-145 database preserves Channel records, memberships and M9's recorded ownership. Legacy Channel writes use the older schema until the M4 columns exist.

`channel_records.visibility_json`, `policy_json` and `owner_human_id` are canonical. `channel_admins` stores explicit admins. Existing public flags become public visibility; all other records default to private. Existing groups retain their recorded Human owner, falling back to the current Host Owner when none was recorded; new groups belong to the creating Human. The boolean column remains only for the M1 alias. Visibility mutations update both representations in one transaction.

Audience queries require an active caller. A role-restricted Channel requires a matching current role even when membership remains. Private groups require current membership, including for the Host Owner. Public and eligible role groups support preview; joining is explicit and posting requires membership. Joined Channel lists, unread counts and live subscriptions use the joined audience. Private-content viewing is not enabled here. Historical removal/purge notices require retained membership and current role qualification, separately from permission to read deleted content.

Human DMs use a deterministic hash of the sorted pair of Human IDs, `type: dm`, an empty Bot `members` array and exactly two `humanParticipants`. Both participants receive canonical Channel memberships. Lists resolve the other participant's current display name. No Bot admission occurs for a Human DM. Existing attachment storage, binding and files pagination are reused. Store reads and SQL search filters exclude everyone outside the pair, including the Host Owner.

Policy checks run at the Host boundary and again at canonical message append after asynchronous attachment preparation. Channel rename/avatar and Bot invitation management also consult the Service. Restricted posts return `channel-post-restricted`; selected All Bots mentions return `channel-mention-restricted`. Other policy refusals return `permission-required` with `details.permission` equal to `addMembers`, `addBots` or `editDetails`. Ordinary member Channel settings omit fingerprints, invitation policy, wake policies, invitations and join requests. Channel owners/admins retain their existing management snapshot alongside the new fields.

Audience/permission revocation invalidates remote-access snapshots, disposes existing browser Peers, closes paired-device mux streams through the pairing authority and closes live roster/Channel subscribers before mutation responses complete. Grants are retained for fresh admission under current permissions. Queued frames recheck audience at delivery. No-op visibility writes preserve existing connections. Role creation and permission additions invalidate admission without disconnecting existing devices; role/permission removal disconnects them.

## Wire contract

All setters return `null`. IDs come from the caller's scoped views, never from a client-supplied actor.

| Method                  | Payload                                                                                              | Result                                                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `channelVisibilitySet`  | `{ channelId, visibility: { kind: 'public' } \| { kind: 'private' } \| { kind: 'roles', roleIds } }` | `null`                                                                                                                 |
| `channelAdminsSet`      | `{ channelId, humanIds }`                                                                            | `null`; Channel owner only                                                                                             |
| `channelPolicySet`      | `{ channelId, policy: { addMembers, post, mentionAll, addBots, editDetails } }`                      | `null`; every policy key is required, with value `everyone` or `admins`                                                |
| `browsableChannels`     | `{}`                                                                                                 | `[{ channelId, name, description?, memberCount, joined, visibility: 'public' \| 'roles' }]`                            |
| `channelJoin`           | `{ channelId }`                                                                                      | `null`; invisible or unjoinable IDs return `channel-not-found`                                                         |
| `channelGet`            | `{ channelId }`                                                                                      | `{ channel, role: 'owner' \| 'admin' \| 'member', policy, visibility, admins: [{ humanId, displayName }] }` for groups |
| `channelRoleDirectory`  | `{ channelId }`                                                                                      | `[{ roleId, name }]`; authorized Channel managers only; no permission lists or member counts                           |
| `channelHumanAdd`       | `{ channelId, humanId }`                                                                             | `null`; enforces `addMembers`, active target, role eligibility and delegation ceiling                                  |
| `channelDescriptionSet` | `{ channelId, description }`                                                                         | `null`; enforces `editDetails`                                                                                         |
| `teamDirectory`         | `{}`                                                                                                 | `[{ humanId, displayName }]`; active recipients only, excludes caller                                                  |
| `humanDm`               | `{ humanId }`                                                                                        | `{ channel }`; active, distinct Humans, caller requires `dm.humans`                                                    |
| `humanDmByUsername`     | `{ username }`                                                                                       | Same authorized DM operation; CLI username resolution stays inside the Host                                            |

`publicChannels`, `publicChannelJoin` and `channelPublicSet` remain aliases. Unknown roles return `role-not-found`. Missing/inactive/self DM targets return `member-not-found`; a missing DM permission returns `permission-required` with `details.permission: dm.humans`. Input shape errors return `invalid-input`.

CLI forms: `channels visibility <id> public|private|roles:<ids>`, `channels admins <id> --set <humanIds>`, `channels policy <id> --post admins --mention-all admins --add-members admins --add-bots admins --edit-details admins`, `channels browse`, `channels join <id>`, `channels get <id>`, `channels roles <id>`, `channels add-member <id> <humanId>`, `channels description <id> --body-stdin`, `team-directory`, `dm <username>` or `dm --human-id <id>`. Every form supports `--as`; partial CLI policy edits first read the current full policy under that same identity.

## Performance and verification boundary

Audience admission, the bulk visible-ID set and browsable Channel discovery each use one database read; the 1,000-Channel regression asserts these budgets. Lists and unread filtering use one bulk set instead of querying permissions per Channel. SQL search applies audience filters before pagination. There are no new dependencies, workers, timers or model calls. Existing message append adds current policy checks only for Human writes; Bot causation/admission remains unchanged.

Host/CLI evidence, rendered Client behavior, installed native behavior and Human acceptance remain separate gates. The UI owner must connect visibility/role selection, admins and five policy rows; use the member role plus post policy for the announcement composer; connect `teamDirectory`/`humanDm`; add bilingual UI copy and release fragments; update the public CLI guides and feature-map user journeys. This logic branch does not modify Client/mobile screens or UI copy.
