# DeepSeek Harness GenUI ecosystem — 2026-11-07

## Scope and evidence standard

Retrieved **2026-11-07 (Asia/Tokyo)**. This is read-only Internet/source research, not an installation, security certification, performance benchmark, or runtime acceptance report. No Host, model, browser automation, Simulator, or Emulator was launched. No upstream tests or published demonstrations were rerun. Only this research document is authored by this task; the shared checkout's existing changes are outside its scope.

The DSH Skill's Context and Decision Tree were read first. Accordingly, **Slots** are a Web Client Registry/Registration seam; a Plugin/Fiber owns lifecycle; a Service Definition/Provider owns operations; **SessionEvent** and Session Persistence own durable execution facts; Conversation Assembly produces presentation. A generated artifact, UI action protocol, state slot, and BotHarness Channel mapping below are **application-defined**, not new DSH-native guarantees. Service Isolation and Agent Scope are not browser sandboxes.

Evidence labels:

- **Docs**: an upstream maintainer's documentation, compatibility statement, or test report. Not independently reproduced.
- **Source**: implementation or manifest inspected at the exact identity below. Describes a code path, not proof it runs successfully in BotHarness.
- **Inference**: integration/security/performance judgment derived from those sources.
- **Runtime**: **not performed for any candidate**. Native/mobile/IM/Human acceptance likewise remain unverified.

Discovery used official GitHub repository search, [discussion #2114](https://github.com/deepseek-ai/deepseek-harness/discussions/2114), and the local September survey as locators. Web search/open returned no usable content in this research session; primary pages and source were retrieved directly over HTTPS using the GitHub API, official documentation site, and npm registry. The scope is nine confirmed community repositories, not a claim to enumerate every plugin or fork.

## Executive findings

1. **DSH already has structured tool presentation and extensible React UI, but these are not a universal GenUI protocol.** Native `presentCall`, `presentResult`, `output.presentationMeta`, Conversation Nodes, and Slots support trusted plugin-authored rendering. The inspected native card union is generic/terminal/diff/search/read/web, not an arbitrary A2UI/TSX renderer. Community Plugins supply the missing authoring dialect, renderer, state semantics, and callback contract. [Native tool contract](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/presentation.ts), [Slots](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/slots.md).
2. **The ecosystem is not one interchangeable “dsh-genui.”** There are guarded `dsh-ui` JSON cards, OpenTiny/Vue `schemaJson`, A2UI documents, incrementally compiled TSX, versioned compiled React artifacts, and a DIL/Worker path with an HTML escape hatch. Package names and persistence differ materially. See the source identity register and family sections below.
3. **Streaming has several different meanings.** Rendering complete JSON components from a growing fence, folding tool-argument deltas before execution, compiling incomplete TSX, and showing only a pending title before compiling a final artifact are not equivalent. “Supports streaming” alone is not a selection criterion.
4. **Saved UI is not necessarily model-readable or cross-device state.** Session-persisted source/metadata, browser-local form values, Host-owned versioned artifacts, and explicit logged action submissions are separate authorities. In particular, `localStorage` does not become PersonaBot Memory or a shared Channel record.
5. **Sandbox claims need source-level qualification.** The #2114 implementation has explicit CSP/capability machinery; DIL uses an opaque iframe plus Worker. MindLab's locked renderer executes blob modules in the Web Client document. Jessen's `allow-scripts` iframe does not itself establish the README's claimed network prohibition. None was penetration-tested here.
6. **No surveyed Web renderer establishes native-mobile or IM parity.** All nine inspected manifests declare a Web Client half. Mobile browser layout, native Expo components, CLI localhost pages, and Lark/Discord interactive messages are different delivery paths. A practical BotHarness design must own fallback, identity, authorization, and callbacks rather than equate a DSH Session with a Channel.

## 2. What is DSH-native today?

### 2.1 Structured Tool results, not arbitrary generated components

**Source:** `ToolDefinition` has a canonical `output` schema and `execute`, optional pure `presentCall(args)` and `presentResult(args, result)`, and `output.presentationMeta(args, value)`. `output.render` produces model-facing `ContentBlock[]`; presentation metadata is a distinct JSON projection. `tool/result.meta` is serializable Session data and can reconstruct a card on replay. Presenter callbacks must not perform an action merely because a history view renders.

At this SHA, `ToolCallView` is generic/terminal/diff. `ToolResultView` adds search/read/web. These typed intents provide native structured display of common tool results; they do not allow a model to name an arbitrary React component or execute TSX by returning a card tag. A custom tool can instead own a custom Slot Registration and metadata schema. Without its renderer, raw result content is the important fallback.

Primary sources: [Tool definitions](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/contracts.ts), [presentation union](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/presentation.ts), [Session types](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/session/src/types.ts), [Tool reference](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/tools.md).

### 2.2 Slots and Conversation Assembly

**Source:** `tool.call.toolview` is keyed by the wire tool name, Session-scoped, and receives a discriminated `preparing` / `start` / `result` phase. Preparation arguments may be incomplete and use the current lazy argument interface. A typo in a registration key will not render; occupying an existing key replaces its view.

`conversation.chat.node` supplies keyed Conversation Node presentation; plugins can register Conversation event definitions and render their own data rather than replace the entire application. Current Slots have **five** cardinalities: `single`, `list`, `keyed`, `chain`, and **`hoc`**. The installed foundation Skill's four-way decision branch is useful conceptually but is not a current inventory: `hoc` exists in this November source. Its layers can remount enclosed content when registrations change, relevant to form state and focus.

Slot declarations and Registrations follow Fiber effects. A contribution should use the owning declaration's lifetime through `slots.inject`; scopes (`root`, `session-maybe`, `session`) bind component data, not isolation of arbitrary JavaScript. Slots are typed React composition, not a sandbox.

Primary sources: [Tool Slot contract](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-tool/src/client/contract/slots.ts), [Chat Slot contract](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/ui-chat/src/client/contract/slots.ts), [Slots reference including hoc](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/slots.md).

### 2.3 Streaming, persistence, and callbacks are separate seams

**Source:** Host Services own mutation, persistence, and streams. Typert Remote/API Gateway connects them to Client models; Conversation Assembly and Slots render those models. UI callbacks close over the appropriate Client service/Remote API. API Gateway owns `/api`; adding a competing interceptor is not a GenUI integration technique.

Live assistant chunks and a durable settled event are different representations. A pending Tool card is not evidence of progressively usable generated UI. Likewise, a persisted artifact document is not evidence that form drafts survive reload, fork, another browser, or another device. Action authorization is a Host operation concern; a renderer and its `postMessage` payload do not establish permission.

Primary sources: [Web Client architecture](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/web-client.md), [Session contract](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/session.md).

## 3. Community implementation families

### 3.1 #2114: pengyue-polaron — versioned compiled React artifacts

**Docs vs current identity:** #2114 still describes `v0.13.2` and a broad old `^0.1.0-rc.6` compatibility claim. Current inspected source is `dsh-plugin-genui@0.15.2`. The discussion is useful discovery, not the current install contract.

**Source:** `genui_create` accepts source files, requirements, and declared capabilities; esbuild-wasm builds the React artifact. An artifact registry retains versions, compiled outputs, per-Session state, and grants; writes use temporary files/rename and private file modes. This is an application-owned disk authority, not merely a JSON fence retained in conversation text. Generated code has state/reporting helpers, and `genui_*` tools provide the Agent-side artifact workflow.

**Streaming:** the compatibility work uses lazy argument `textPrefix('title', 256)` for a pending title. The source inspected builds and verifies a candidate before exposing its compiled preview; it does **not** establish rendering every incomplete TSX prefix as it streams. Do not equate title streaming with MindLab's incremental compilation.

**Isolation/actions:** the preview response includes CSP `connect-src 'none'`, `frame-src 'none'`, and `sandbox allow-scripts allow-modals`. The surrounding host page has a different policy. A MessageChannel/nonce bridge mediates `state/read`, `state/write`, `tool`, and `external`; private capability tokens and source/origin checks are part of the bridge machinery. Host control actions are refused from sandboxed apps. Tool capabilities must be declared, match their grant fingerprint and Session, and be granted before reaching `ctx.tools.execute`. External access follows declared credential-free HTTPS destinations/methods, rather than handing arbitrary MCP credentials to page code.

**Caveats:** these are meaningful source controls, not an independent sandbox audit. The manifest explicitly includes tested DSH `0.2.1-rc.2`–`rc.3`, not every later prerelease; November `0.2.2-rc.1` is outside that bounded interval. The October compatibility report distinguishes its own installed Web checks from absent paid-model/native-desktop checks. Source paths, saved state, grants, expiry, and task identity need migration/replay tests before reuse.

**BotHarness fit (Inference):** useful reference for richer, versioned task-local apps and explicit connected-tool consent. Not a drop-in for Channel ownership, PersonaBot Memory, or native mobile. Its CLI localhost page is a browser URL on the Host machine, not terminal-native widgets or a phone-accessible service by default.

Primary sources: [manifest](https://github.com/pengyue-polaron/deepseek-harness-genui/blob/d24d91e3b6462aae498fa8452abcb44e3c53e9d5/package.json), [tools](https://github.com/pengyue-polaron/deepseek-harness-genui/blob/d24d91e3b6462aae498fa8452abcb44e3c53e9d5/src/tools.ts), [builder](https://github.com/pengyue-polaron/deepseek-harness-genui/blob/d24d91e3b6462aae498fa8452abcb44e3c53e9d5/src/artifacts/builder.ts), [registry](https://github.com/pengyue-polaron/deepseek-harness-genui/blob/d24d91e3b6462aae498fa8452abcb44e3c53e9d5/src/artifacts/registry.ts), [server/CSP/execution gate](https://github.com/pengyue-polaron/deepseek-harness-genui/blob/d24d91e3b6462aae498fa8452abcb44e3c53e9d5/src/runtime/server.ts), [bridge](https://github.com/pengyue-polaron/deepseek-harness-genui/blob/d24d91e3b6462aae498fa8452abcb44e3c53e9d5/src/runtime/bridge.ts), [grant checks](https://github.com/pengyue-polaron/deepseek-harness-genui/blob/d24d91e3b6462aae498fa8452abcb44e3c53e9d5/src/runtime/permissions.ts).

### 3.2 omdsh-dev — guarded declarative `dsh-ui`, not generated JavaScript

**Source:** `@changfenhuang/dsh-genui@0.16.0` renders JSON component specifications from `dsh-ui` fences and a `render_ui` tool. `guard.ts` and the runtime schema normalize/validate a component vocabulary. `parse-partial.ts` recovers completed component prefixes with a bounded candidate/parse budget; malformed tails need not block earlier complete items. The browser half includes plugin-owned DOM fence mounting and a keyed Tool view; code comments explicitly distinguish this from a hypothetical host fence registry. Do not promote that optional community registry into a DSH-native API.

**Actions:** local controls can update without a model round-trip; explicit action payloads go through the owning Session's `conversation.send` as model input. Panel-send failure is caught/logged and can drop an action while the panel stays interactive. This is a model continuation protocol, not proof of exactly-once delivery or an authorized business mutation.

**Persistence:** `interaction-store.ts` uses browser `localStorage`, keyed by Session/block/content fingerprint, bounded to 200 blocks with LRU eviction. The `render_ui` tool's repaired specification travels in result metadata and the toolview republishes settled specs to the panel store. These are different stores: reconstructing a spec from Session history does not make its user's unsubmitted values available to the model or another device.

**Isolation:** guarded data rendered by trusted components is a substantially narrower design than arbitrary TSX. It is not an isolated browser process; links/media, SVG/Mermaid/math/chart implementations, asset loading, and resource limits still matter. The README's “zero eval” and fast-interaction figures are maintainer claims; this investigation did not audit every component or benchmark them.

**BotHarness fit (Inference):** the most directly reusable reference for a small declarative form/chart slice, especially if implemented as a renderer over an application-owned contract rather than by observing the entire conversation DOM. Keep message identity and callbacks explicit. Multiple plugins claiming `dsh-ui` or `render_ui` should not be presumed composable.

Primary sources: [manifest](https://github.com/omdsh-dev/dsh-genui/blob/c2624ce0e08fd18510bef640168fcb81e817ed58/package.json), [browser integration/actions](https://github.com/omdsh-dev/dsh-genui/blob/c2624ce0e08fd18510bef640168fcb81e817ed58/src/client/index.tsx), [partial parser](https://github.com/omdsh-dev/dsh-genui/blob/c2624ce0e08fd18510bef640168fcb81e817ed58/src/client/parse-partial.ts), [guard](https://github.com/omdsh-dev/dsh-genui/blob/c2624ce0e08fd18510bef640168fcb81e817ed58/src/client/guard.ts), [interaction persistence](https://github.com/omdsh-dev/dsh-genui/blob/c2624ce0e08fd18510bef640168fcb81e817ed58/src/client/interaction-store.ts), [Tool renderer](https://github.com/omdsh-dev/dsh-genui/blob/c2624ce0e08fd18510bef640168fcb81e817ed58/src/client/toolview.tsx).

### 3.3 lhuans — OpenTiny/Vue `schemaJson`

**Source:** the unscoped package **`dsh-genui@0.3.1` is this repository**, not omdsh's scoped package. It splits assistant text into Markdown and `schemaJson` fences/XML tags, including trailing incomplete schemas while streaming or interrupted. A React wrapper feeds a lazily loaded Vue custom element using OpenTiny's `GenuiRenderer`; inspected build dependencies pin OpenTiny GenUI packages to `1.4.0`. The custom element deliberately has `shadowRoot: false` so TinyVue overlays/theme CSS use light DOM.

**Actions/persistence:** a registered `continueChat` custom action constructs message plus state JSON, calls `inputActions.setDraft`, then `submit`. The source inspected proves a conversation callback and reconstructible assistant source, not Host-persisted form drafts. Overwriting/continuing an existing draft needs product-specific testing.

**Integration/isolation:** the plugin shadows the built-in `assistant-step` renderer, captures its registration, and borrows its reasoning-body Slot. That is a larger compatibility surface than registering one new Tool key. Source provides no basis to describe its light-DOM Vue component as a security sandbox. The entire OpenTiny expression/action engine was not audited.

**BotHarness fit (Inference):** potentially attractive for a broad material/component inventory, but higher renderer-replacement and React/Vue/theming cost. The November 6 DSH 0.2.2 fix is a useful maintenance signal, not installed compatibility evidence.

Primary sources: [manifest/build dependencies](https://github.com/lhuans/dsh-genui/blob/6328c64a0f0c4728a79ec5fe90818e0866f57045/package.json), [Slot replacement](https://github.com/lhuans/dsh-genui/blob/6328c64a0f0c4728a79ec5fe90818e0866f57045/src/client/index.ts), [fence splitting](https://github.com/lhuans/dsh-genui/blob/6328c64a0f0c4728a79ec5fe90818e0866f57045/src/client/split-assistant-text.ts), [callback](https://github.com/lhuans/dsh-genui/blob/6328c64a0f0c4728a79ec5fe90818e0866f57045/src/client/GenuiAssistantNodeView.tsx), [Vue/light-DOM runtime](https://github.com/lhuans/dsh-genui/blob/6328c64a0f0c4728a79ec5fe90818e0866f57045/src/client/genui-card-element.ts).

### 3.4 MindLab — genuine incremental TSX compilation, main-document execution

**Source:** `dsh-generative-ui@0.2.0` supports inline `ui4a/tsx` and workspace files under `ui4a/canvases/<id>.ui4a.tsx`. It observes Session text as well as DOM surfaces, incrementally delivers code to `partial-react`, compiles through `@esm.sh/tsx`, retains last useful visuals, and handles incomplete-frame errors differently from settled failures. This is actual source machinery for rendering while JSX remains incomplete, not just a spinner or streamed title.

**Critical isolation distinction:** `bun.lock` resolves `partial-react@0.0.10`. The exact published npm tarball was fetched and inspected in memory; its SHA-512 integrity matches that lock:

`sha512-h6e2sA/SGxcB+or3j6ydrmG4D6lB2nkovaER6yYNhEQkRv+rkR0ilZRMz0B/vh5AqA/dOAVL7cLc8AwepaASqg==`

In that package, `package/src/runtime.ts` calls `createRoot(target)` and dynamically imports generated JavaScript from a blob URL. This is execution in the embedding Web document, not an opaque iframe/Worker sandbox. A WASM compiler and an import map do not change that boundary. Runtime binding hardening around captured intrinsics and capability URLs does not make arbitrary generated DOM JavaScript untrusted-safe. Remote dependency fallback uses esm.sh, adding an availability/supply-chain path beyond the local plugin.

**Actions/state:** `$dsh/*` bindings connect generated code to chat and plugin-owned filesystem/model/command/search routes. `$dsh/state` uses `localStorage`; its own source explicitly notes that two cards choosing the same key share state, rather than isolating it by card/Session. Workspace canvas files can outlive a turn; that is not the same as cross-device persisted control state.

**Performance:** compiler comments report a 2.6 MB WASM file, approximately 16 MB instantiated heap, and cold-init costs. These are upstream developer observations, not measured results here. Recompilation, dependency probes/retries, UI state preservation, and execution privileges need separate budgets and threat review.

**BotHarness fit (Inference):** a strong reference for partial-code rendering research or explicitly trusted developer-generated apps; **not a safe default for untrusted model-authored UI in the main product document**. Any adoption would need an independently designed execution/permission boundary rather than relying on the compiler name.

### 3.5 Valuz — A2UI tool arguments, transient streaming, durable settlement

**Source:** `generate_ui` takes a native JSON array of A2UI messages, not a stringified document. The model authors the UI; the tool itself validates/serializes rather than calling a second model. It sanitizes against the Valuz catalog and applies a default 262,144-byte document cap. The client registers its own Conversation event definition and keyed Chat Node, plus a turn-tail entry so settled surfaces remain visible outside collapsed process output.

**Streaming/persistence:** a call-ID-keyed fold consumes `assistant/live-chunk` / `tool-call-delta`, extracts completed objects from the partial `messages` array, and renders them through `A2UIRenderer`. A settled `tool/result.meta` document supersedes that provisional view; durable call arguments and result metadata rebuild the surface after reload. Ephemeral tab/form state is not thereby persisted or model-visible.

**Actions/isolation:** `<ui_action …>` is sent as an ordinary message to the owning Session through `conversation.send`. The dependency renderer maps declarative components to trusted React; this is not arbitrary TSX, but also not a browser sandbox. The transitive renderer/catalog was not exhaustively audited. The README acknowledges coarse host token integration, a large inlined bundle, and model round-trips for actions; its size/token figures are not independently measured here.

**Important PTC qualification:** the plugin README says Code Mode loses surfaces because nested dispatch has no metadata. Treat that as a dated compatibility explanation, **not a universal fact about November DSH**. The inspected plugin's node matcher handles direct calls/live chunks/results, not `tool/ptc-dispatch`; current native Tool output contracts separately promise replayable presentation for native and nested calls. Even an upstream metadata improvement does not automatically add the missing plugin matcher. Direct-call and PTC paths require separate verification.

**BotHarness fit (Inference):** the clearest reference for separating provisional UI from canonical Session metadata and logging model-visible actions. Reusing its A2UI protocol requires a product-owned renderer and callback path on each supported surface; importing its Web Plugin alone does not deliver that parity.

Primary sources: [README including limitations](https://github.com/valuz-ai/dsh-valuz-genui/blob/7c5f28f5c4610ef0d61d27798c0118a46e433bef/README.md), [validation/output projection](https://github.com/valuz-ai/dsh-valuz-genui/blob/7c5f28f5c4610ef0d61d27798c0118a46e433bef/src/tool.ts), [Conversation fold](https://github.com/valuz-ai/dsh-valuz-genui/blob/7c5f28f5c4610ef0d61d27798c0118a46e433bef/src/client/node.ts), [partial argument extraction](https://github.com/valuz-ai/dsh-valuz-genui/blob/7c5f28f5c4610ef0d61d27798c0118a46e433bef/src/client/partial-args.ts), [Slot registrations](https://github.com/valuz-ai/dsh-valuz-genui/blob/7c5f28f5c4610ef0d61d27798c0118a46e433bef/src/client/index.tsx), [action bridge](https://github.com/valuz-ai/dsh-valuz-genui/blob/7c5f28f5c4610ef0d61d27798c0118a46e433bef/src/client/action-bridge.ts).

### 3.6 yunyv — DIL in a Worker, versioned artifacts, separate HTML path

**Source:** `dsh-intelligent-ui@0.1.1` has an `artifact` tool with create/patch/read/list/destroy, exact-text patching, and a disk catalog/version store. Content files and metadata are separate; an atomic index update follows content/sidecar writes. Source comments describe recovery from partially committed versions. The UI can render an artifact marker inline and in a right-side panel.

**Isolation:** the DIL path compiles a constrained language, executes its program inside a blob/data Worker inside an opaque `sandbox="allow-scripts"` iframe, and returns a serialized element tree for the Host DOM renderer. Its frame policy uses `default-src 'none'`, a hash-pinned bootstrap, and restricted Worker sources; `unsafe-eval` is deliberately used for the program evaluation. That is a concrete separation mechanism, not “no evaluation.” The raw HTML escape hatch has **a separate resource/CSP policy** and must not inherit DIL's stronger no-network description by association.

**Streaming/actions/state:** the HTML artifact view incrementally pumps partial markup with a 120 ms minimum gap. DIL compiler recovery and long-lived mounts support revisions and control-state adoption, but this source review does not establish that both engines have identical pre-settlement streaming behavior. DIL keyed control state is shared across mounted views by an in-memory map. A Human-operated button sends an interaction report through the current input insertion/capture mechanism and submits it. Persisted artifact versions, state retained during a patch, and durable cross-restart control values are different claims; the latter was not established here.

**BotHarness fit (Inference):** an interesting candidate when local computation must be separated from DOM/network, with a narrower DSL rather than unrestricted TSX. The version store and DIL protocol add substantial lifecycle/migration obligations. The README's test counts and upstream protocol compatibility are author reports, not our acceptance results.

Primary sources: [tool contract](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/tool.ts), [versioned disk store](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/store/disk.ts), [sandbox host](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/client/dil/sandbox.ts), [DIL frame policy](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/client/dil/frame.ts), [HTML policy](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/client/frame.ts), [state sharing](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/client/dil-state.ts), [interaction callback](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/client/fence.tsx), [HTML streaming view](https://github.com/yunyv/dsh-intelligent-ui/blob/c4920ad2327ee5dfdfb42744e4696286868d934e/src/client/ArtifactView.tsx).

## 4. Cross-surface limitations and practical BotHarness fit

### Product boundary: a Session is not a Channel

Local provenance: BotHarness checkout HEAD was `1532839bc9042f2e749de321dd4bfa3b67cb3eb0`, **dirty**, during research. Product vocabulary was read from the working-tree `CONTEXT.md`; the mobile Markdown implementation was spot-checked in `apps/mobile/src/ui/markdown-view.tsx`. These are local observations, not a clean-commit attestation. The latter uses React Native `EnrichedMarkdownText`, not DSH's browser Plugin loader. No BotHarness runtime integration was tested.

**Inference:** upstream plugins commonly route to one DSH Session. BotHarness's persistent PersonaBot, Channel, Orchestrator Session, Assignment Session, Source Event, Admission, and Outbox are application-defined ownership boundaries. A Channel can outlive the particular Session that generated a card. A card action must resolve current, authorized product ownership, not just the currently selected conversation or a caller-supplied `sessionId`. A tool result in an Assignment's Trajectory also need not become a published Channel message automatically.

### Desktop/Web, native mobile, IM, and CLI

- **DSH Web/desktop Web surface:** likely integration target because the inspected manifests declare `dsh.client.platform: "web"`; still needs installed-module activation, exact Slots API compatibility, coexistence with BotHarness's own Client surfaces, keyboard/focus/accessibility checks, and real model/tool paths. A desktop shell hosting a Web Client is not native-mobile acceptance.
- **Native Expo mobile:** React DOM, Vue custom elements, browser `localStorage`, `srcdoc`, MutationObserver, and esm.sh imports are not an automatic React Native implementation. Either render a deliberately restricted portable schema with native controls or design an explicitly isolated Web surface; neither exists merely because the plugin is installed on the Host. Native iOS/Android interaction and action authorization remain separate gates.
- **Phone browser:** responsive CSS is not a test result. Host reachability, authenticated origin, trust, capability-token handling, keyboard/viewport/focus, and recovery after suspend must be verified. A CLI `localhost` URL points to the phone itself if copied unchanged.
- **Lark/Discord/other IM:** none of the inspected paths establishes adapter-specific cards/components plus authenticated callback ingress, sender identity, event deduplication, or product Admission/Outbox handling. Do not ship executable HTML/TSX as an IM message and call it portable UI. Use a readable summary or protected external artifact link first; native IM interactions require their own supported schema and verified callback path.
- **CLI:** a browser page launched from CLI is not headless parity. Read/create/inspect/action/refusal behavior must be operable directly by the agent without a model or Web UI under BotHarness's CLI policy. No community README proves that product requirement.

These are compatibility constraints inferred from the linked implementations/manifests, not claims that every community author explicitly rejects mobile or IM. No surveyed project was found to provide a verified end-to-end BotHarness native/IM adapter in the inspected scope.

### Recommended narrow first slice — proposal, not implementation

Prefer **trusted rendering of a small declarative contract**, using native DSH presentation/Slots where the product actually owns that surface. Borrow omdsh's bounded partial-data rendering and Valuz's provisional-vs-settled distinction; borrow pengyue's explicit artifact/version/capability thinking only where a real task app requires it. Do not begin by executing unrestricted TSX in the main product document or replacing the entire assistant renderer.

One useful tracer bullet would be a Bot-generated, read-only comparison or a small selection form in one Human DM, with a text fallback and one explicit submit action. Proposed ownership:

1. A versioned application-defined document records its source message, artifact revision, owning Bot/Channel, and originating execution identity. Canonical product persistence owns that document; Session metadata may carry its execution receipt, not create a competing Channel store.
2. The renderer accepts a bounded component/data vocabulary, keeps speculative prefixes separate from the validated settled revision, and retains readable text when unsupported or refused.
3. An application Service validates authenticated Human, destination, revision, allowed action, and idempotency key. Callbacks are untrusted inputs. A submit may become a canonical Source Event/Admission; paid/destructive/external actions still pass the existing approval owner.
4. Acknowledged interaction facts are model-readable through the owning product path. Browser-local drafts remain drafts; durable source, saved choices, business mutations, and PersonaBot Memory are not conflated.
5. The same read/action/refusal seam has a CLI path. Mobile/IM initially get the honest summary/fallback, not a claim that the Web UI is universally rendered.

This requires a product design decision and separate authorization before implementation; this research does not create issues, choose a dependency, or authorize deployment.

## 5. Outstanding verification and selection gates

- **Version gate:** test the exact BotHarness DSH pin and the actual candidate artifact, then separately test current upstream. Broad peer ranges or a recent compatibility commit do not prove load/activation. For pengyue in particular, do not assume its explicit rc.2–rc.3 interval admits rc.5/0.2.2.
- **Streaming correctness:** exercise truncated JSON/JSX, malformed items, cancellation, rewritten prefixes, failures/retries, settle, reload, and direct vs nested/PTC calls. Record when the first meaningful control appears, not only when an empty card mounts.
- **Durability:** independently test document replay, values after reload/restart, fork semantics, two tabs, another browser/device, state expiry/eviction, deleted/archived Bot or Channel, and stale artifact revisions. Make the chosen authority explicit.
- **Security/actions:** review generated-code execution realm, CSP/resources, capability/credential leakage, cross-Session/Channel spoofing, payload bounds, secret-entry prohibition, callback authenticity, Host approval, idempotency, and state-write conflicts. An iframe or schema name is not sufficient evidence.
- **Performance:** establish prompt-token cost, browser bundle/asset transfer, cold compiler/renderer initialization, incremental parse/recompile cost, memory retention, and timeline scroll/virtualization behavior. Upstream “sub-millisecond,” bundle-size, or test-count claims are not our measurements. This document adds no runtime dependency and has no runtime hot-path impact; no runtime performance regression guard is applicable to this docs-only change.
- **Acceptance boundaries:** source review, automated tests, packed install, real DSH Web interaction, real model/tool reply, installed native behavior, live IM callback/rendering, and Human acceptance must be reported separately. **All runtime gates remain unrun here.**

## Bottom line

Native DSH provides the right extensibility seams; community Plugins already demonstrate several real implementations above them. For BotHarness, the useful reusable pieces are bounded declarative rendering, provisional/canonical separation, durable artifact identity, and explicit model-visible actions. The unresolved work is not “can a page be generated?” but whether that page's state and actions obey the product's persistent ownership, security, replay, CLI, and cross-surface contracts. No repository in this survey is established as an installed, safe, cross-platform BotHarness GenUI solution.
