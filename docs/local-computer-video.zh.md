# Local Computer 视频：Windows 到 Android

首片实现面向一块 Windows x64 主显示器和一个 Android 观看端。安装包、真机性能与 Human 验收必须绑定准确构建记录，才能声明通过。其他发送端和容器观看路径保留既有行为。

使用「检查权限」或 `deepseekbot computer-start --target local` 启动本机 Computer。既有的显式安装校验流程会按需安装固定版本采集 helper：Windows x64 Electron 44.9.3，下载量 158,508,870 字节；解压后的占用需在验收机器实测。Host 监管独立 helper 进程。Android 新增本机视频模块，必须重建开发客户端，旧客户端仅刷新 JavaScript 不够。

安装还会直接调用系统 .NET Framework 编译器，编译随包提供的 Windows Job 启动器，不启动编译服务。此步骤有时间上限，仅在明确安装时执行；观看不会下载或编译 helper。编译、校验或桌面访问失败时，视频保持不可用。启动器拥有完整 Electron 进程树；清理未确认时禁止再次采集，不把根进程退出当作清理成功。

打开已启用 Computer Access 的 Bot，选择「Computer」。观看不会暂停 Bot。「接管」先保存整台 Computer 的暂停状态，再等待正在执行的 Bot 操作结束。单指移动大光标，轻点画面或图标加文字的「左键」「右键」在光标位置点击。拖动任一鼠标按钮可横向或纵向滚屏，滑块随拖动响应，松手不触发点击。观看或接管时均可双指自由缩放、平移顶对齐的手机预览，松手保留位置，「归位」恢复默认适配。Computer 支持 Android 横屏，左键与右键之间增加独立二维滚动区，命令位于下一行，右上角退出。系统大字下命令行可横向滚动。原生手势与文字输入验收须绑定具体构建。

先点击电脑上的输入框，再点「键盘」拉起手机原生输入法。手机不显示额外输入框、发送栏或重复功能键；确认的文字直接输入电脑，中文候选留在输入法内，确认后才传输。原生退格、回车作用于电脑。收起键盘、切后台或失去控制时丢弃未完成的组合输入。所有输入继续经过现有顺序队列和授权检查，结果不确定时不会重发。原生焦点不再受 React 输入框 ref 或视频更新影响；预览把光标保留在键盘上方，「交还 Bot」保持可达。此原生模块需要重新构建 Android App；真实输入法与键盘布局仍需按具体构建验收。

Host 在该观看端首次输入前关闭它独有的驱动虚拟光标，并等待同一会话的渲染状态确认已关闭；确认缺失或无效时拒绝输入。手机本地光标保留，点击不再等待重复光标动画。授权检查和输入排空继续生效，这不代表已测得延迟数据。

## 无副作用输入测试页

在 Windows 运行 `node scripts/computer-input-fixture.mjs 4488 60`，打开 `http://localhost:4488/`。
页面提供横向、纵向、二维滚动区及偏移读数，还有普通、多行、密码输入框和点击计数器。
把远端光标移到对应区域后拖动滚动区，检查偏移与松手无点击。只输入虚构测试文字。
内容仅留在浏览器内存；服务器只监听本机，只提供此页，并在指定分钟数后退出（1–180 分钟）。
浏览器页面验证不等同于手机手势验收。

视频与输入使用主显示器的物理像素尺寸。授予控制和每次输入之前，owner 都比较 Windows 驱动报告的尺寸与采集尺寸；不会重复乘以 DPI 缩放比例。尺寸不匹配或发生变化时拒绝输入。

接管后，同一个按钮变为「交还 Bot」：一次明确操作结束接管，等待 Human 输入执行完毕，再保存 Bot 恢复状态，预览继续观看。它使用既有 owner `resume` 命令；底层 CLI `release` 仍保持 Bot 暂停。退出、手机失联、helper 失败和 Host 重启都保持暂停，重启不会恢复旧控制权。媒体无法启动时，仍可通过 CLI 明确恢复。

手机切后台或锁屏会停止媒体、释放控制；回到前台仅恢复观看，需要再次明确接管。第二观看端收到 `viewer-limit`，不会挤掉第一端。画面停滞或新鲜度未确认时禁止输入。静态活画面仍须通过真机验收；重复 canvas 帧不能单独证明采集正常。

新观看端没有自动或手动图片回退。本机能力缺失、协商失败或媒体中断会显示拒绝与重试状态，不轮询 `/api/computer/frame`。迁移后的 Windows 本机 Computer 对旧帧、输入和接管入口返回 `update-required`。Bot 截图是独立能力，暂停期间同样拒绝。

T1 使用直连 WebRTC，未配置 STUN/TURN。手机的信令和控制复用既有加密 LAN 通道、固定 Host 密钥和已批准的设备身份；只有服务端拥有的 LAN listener 才把准确的视频命令路径直接分派给 Computer owner。Hosted Connect 虽已具备加密 carrier，仍返回 `connect-carrier-required`；远程媒体验收属于后续切片。没有 WebView 或明文回退，也没有自配 TURN、音频、剪贴板、后台观看或解锁功能。

画面停滞时禁止输入，但「交还 Bot」、退出和「重新连接」仍可用。Computer 暂停或调用者保留 grant 时即可明确交还，与能否输入分开。重新连接先关闭旧 attempt，再恢复观看，不恢复控制权、不恢复 Bot、不重放输入。

## 连接排查

手机无法连接局域网 Host 时，请把手机连到电脑所在的 Wi-Fi，允许本地网络访问，并在电脑的「设置 → 设备」中开启局域网连接，再点「重试」。仅打开 Wi-Fi 而没有连接网络还不够。远程连接则提示检查手机网络、电脑未休眠且 DeepSeekBot 正在运行；不能从一个错误就断定是 Wi-Fi 故障。

Host 断线时，即使尚未创建观看端，Computer 也保留「重试」入口。仅视频失败时，确认电脑未休眠且 Computer 正在运行，再点「重新连接视频」；设备被拒绝时提供「重新配对」。二维码过期仍需换新码。这些动作不会接管或恢复 Bot；输入结果不确定时，仍优先提示查看画面后再决定是否重复操作。

## 恢复与降级

接管后不能安全地仅回滚代码：旧版本忽略 `botharness/computer-pause.json`，重启可能重新放行 Bot。保持受影响的 Computer 停止，确认其媒体已停止，并保留暂停记录。只有 Human 明确选择恢复 Bot 时，才在降级前通过新版本支持的恢复操作排空输入并恢复；否则使用继续遵守持久暂停的向前修复。不可为了降级自动恢复或删除暂停记录。

## Agent 操作

手机、认证 Host／Device gateway 与 CLI 消费同一个 Computer owner。通过 [CLI 命令](bot-cli.zh.md#local-computer-视频) 查看暂停、全局观看与控制状态、协商和明确恢复。`controller` 与 grant 只属于调用者；`viewerCount` 和 `controlHeld` 表示全局状态。CLI 不打印私密信令内容。

控制心跳静默 6 秒后停止接收输入，30 秒内释放控制保留与媒体。接收端呈现计数须在 5 秒内前进；helper 独立要求 2 秒内真实采集进展及 4 秒内编码进展，与桌面内容是否变化分开判断。命令和 drain 最多等待 10 秒，清理最多等待 3 秒。owner 最多接收八个待处理命令，并独立限制本机输入积压；请求体上限 128 KiB，SDP 上限 96 KiB。超限返回 coded refusal，不恢复 Bot。

## 验收

[本机验证旅程](../.agents/skills/verify-deepseekbot/features/local-computer-video.md) 覆盖控制栅栏、已建立媒体的撤销、静态活画面和运动场景测量。采集计数、解码帧、EGL swap、TextureView 更新与物理屏幕显示是不同指标。须用可见运动帧编号交叉核对绑定 attempt 的呈现计数。声明的 LAN rig 要达到真实呈现至少 15 fps、输入到可见反馈 p95 不超过 500 ms，并保证静态文字可读。单元测试或信令响应不能证明这些结果。

## iPhone 与 Mac

[#2653](https://github.com/BotHarness/DeepSeekBot/issues/2653) 扩展一台 Mac 主屏幕到一个 iPhone 观看者：同 Wi-Fi 下经已配对的加密 LAN 通道观看、明确接管、移动指针并点击、缩放／重置视图、交还给 Bot。iOS 本片不包含 Android 的键盘与滚动控件。按钮遵循触感开关。必须重新构建包含 LanChannel 和 LocalComputerVideo 的 iOS 应用；最低版本保持 iOS 16.4，CocoaPods 校验固定 WebRTC-SDK 144.7559.15 的 SHA-256。

明确启动本机电脑时安装 Electron 44.9.3 的 Apple silicon（130,639,665 字节）或 Intel（134,522,186 字节）运行时；观看不会安装软件。独立启动器拥有采集进程组，关闭、输入管道断开和 Host 退出均清理整组；未确认清理时禁止替换。保留签名应用与内部框架链接。

在 macOS 系统设置中授予采集助手和现有电脑驱动屏幕录制权限，并为输入授予辅助功能权限。缺少采集权限返回 `screen-recording-required`，授权后重启本机电脑再试。iPhone 需允许本地网络访问；Tailscale HTTPS 与托管 Connect 不支持这条视频控制路径。

Mac 视频使用物理像素，输入驱动使用逻辑点。Host 每次校验“逻辑尺寸 × 缩放比例 = 采集尺寸”，点击只除以比例一次；无效比例、尺寸改变或旧控制权均拒绝输入。观看不自动接管，失败不回退截图。

iOS 使用只有一个待呈现帧的 Metal 接收界面，解码、渲染和 drawable 呈现分别计数。后台、锁屏与界面移除立即隔离回调，在后台线程关闭 peer，清理完成前不允许新 peer。源码、原生构建、模拟器、真机画面和 Human 验收分别记录。
