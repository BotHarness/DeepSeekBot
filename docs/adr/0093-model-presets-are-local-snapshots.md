# Model Presets are local snapshots; each Session owns its model route

Status: accepted

ADR-0027 keeps model selection local to a deployment and outside SoulSnapshot. A Human can define a reusable Model Preset containing one Orchestrator provider/model/reasoning-effort route and an Assignment set of exact provider/model routes with allowed and default efforts. Applying a preset copies it into a PersonaBot Model Plan; later edits to the reusable preset do not change existing Bot plans. A Human can edit one Bot's plan without changing the preset. These plans may travel in an identity-preserving Profile Backup, but not in a PersonaBot Export or SoulSnapshot.

The Orchestrator uses the plan's exact route. Its plan change takes effect after the current Turn, at the next Turn's first model request. A new Assignment uses the plan's Assignment default unless the Orchestrator selects an allowed route and effort; every effective choice is checked at the Host execution boundary. An existing Assignment keeps its route when the Bot's plan changes, but an explicit later switch must satisfy the current plan and takes effect on its next request. DSH Subagents inherit their parent's route when it remains allowed; explicit choices must satisfy the Bot's current Assignment set and effort limits. If a retained Assignment uses a route excluded by the new plan, its newly created Subagents use the current Assignment default instead and tell the parent which route was chosen. Unavailable routes, efforts, or credentials stop the request and require Human repair rather than silently switching providers.

The plan is BotHarness application-defined operational authority, distinct from DSH's Agent preset and DSH's deployment-wide model default. DSH SessionEvents remain the durable record of what a Session actually selected and called. A legacy single `model` string migrates only when its provider resolves uniquely; otherwise the Bot requires Human selection before another model request. Keeping preset templates separate from applied snapshots makes rapid switching predictable while allowing different Bots to diverge safely.

## Refinement: independent Orchestrator selection

[ADR-0218](../decisions/sessions.md#adr-0218) allows a Bot Model Plan to fix only its Orchestrator while its Assignment policy continues to inherit the Profile default. Both `assignmentDefault` and `assignmentModels` are absent in that case. Existing complete plans and reusable Model Presets retain their previous semantics. An Assignment without a retained route continues to inherit on later requests, rather than adopting a subsequently configured Bot default.

## Refinement: open Assignment models

[#4416](https://github.com/BotHarness/DeepSeekBot/issues/4416) (spec [#4410](https://github.com/BotHarness/DeepSeekBot/issues/4410)) adds an opt-in open mode to a Model Preset and a Bot Model Plan (`openAssignmentModels`). In open mode an explicit Assignment or Subagent choice no longer has to be in the Bot's current Assignment set: it may name any catalog route that the Bot owner's role allows (`requireBotModel`) and whose provider has a valid credential (`catalog.validate`). Both checks stay at the Host execution boundary, for Assignments and for every Subagent path. A listed route keeps its own allowed and default efforts. The Assignment default stays required and is still used when no model is named. Without the flag every rule above is unchanged.

## Refinement: Routing Groups in Presets

[#4497](https://github.com/BotHarness/DeepSeekBot/issues/4497) lets every Preset slot (Orchestrator, Assignment default, each allowed Assignment entry) hold a Model Choice: an exact route or a Routing Group ([ADR-0355](0355-model-fallback-is-host-owned-at-step-boundaries.md)). A Preset and the Plan copied from it store a Routing Group by id, not by copying its members, so editing a Routing Group applies to every Preset and Plan that names it at the next Turn. The Preset itself stays a snapshot: editing it still does not change Plans it was applied to. Model Fallback stays inside the Routing Group a Session or Assignment was started on; an Assignment started on an exact route has no fallback. A Routing Group entry in the allowed set has its own allowed and default efforts, limited to levels every member supports; with no shared level, each member runs on its own effort. The Host refuses a Preset save that would drop Routing Group fields, so an older client cannot silently turn a Routing Group back into a fixed route.
