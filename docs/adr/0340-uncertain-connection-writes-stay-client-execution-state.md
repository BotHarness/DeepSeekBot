# ADR-0340: Uncertain connection writes stay Client execution state

Accepted for Environment E11 ([#4120](https://github.com/BotHarness/DeepSeekBot/issues/4120)). Stopping the route or revoking the grant carrying a management request can lose its acknowledgement after the owning Host has acted. The Client records an execution guard before one transmission and requires the same pinned Host’s canonical readback before resolving an uncertain result; it never converts ordinary management writes into a replay queue. Device Pairing, private-route and account capabilities remain the configuration and authorization authorities.

The guard lives in execution-only keys under the existing Client HostStorage owner, separately from the SavedHost configuration array. Otherwise another already-open tab’s unrelated whole-array write could erase the unknown-result guard. Its identity binds the Host ID and public key, device grant, operation generation and exact operation/route ID. One shared Web Lock covers prepare/persist, one write and acknowledgement, and fresh readback with generation CAS. Lock waiting and execution obey the request deadline, capped at 30 seconds. Missing Web Locks refuse dangerous writes with guidance to a supported secure page or the owning environment’s local CLI; insecure remote HTTP pages are not claimed equivalent.

A verified alternate route is tested through the existing HostClient, selected by an explicit manual-preference change, observed as the actual connected route and checked with the authenticated Host owner before writing. Without that handover the Human explicitly confirms disconnection. Ordinary manual route policy does not silently fail over. A private route stop names its owning route ID, preserving sibling routes and foreign mappings; account sign-out, relationship disconnect and individual device revocation remain distinct operations.

The existing Owner-only RemoteHosts provider also gates execution-history access and local forgetting. Member and Admin pages do not hydrate Owner credentials or execution records. Its `owner-required` refusal remains an authorization refusal, not a prompt to restore storage. An exact-grant readback refusal retains the unresolved record and never falls back to a Native Owner request.

Account enrollment and manual configuration changes share the existing short credential transaction: fresh-read the raw SavedHost array, compare the exact credential generation, then persist only configuration. Execution projections are derived again after that transaction and never serialized into the credential array. When both are needed, the execution Web Lock precedes this short configuration transaction; configuration writers never acquire the execution lock. Enrollment retains its separate per-Host intent lock before the same configuration transaction.

Changing a device grant does not inherit or replay its predecessor’s write. An older unresolved operation blocks further management mutations on that Host until explicit same-pin readback confirms completion; changing grants cannot bypass it. Recovery route selection and probing remain available. A changed pin refuses that readback. An indexed but missing execution record is a storage refusal, never fresh state or a candidate for silent pruning; saved Hosts and already loaded Feed/conversation data remain available. Restoring the record permits explicit readback. At most 32 unresolved execution facts are retained; further mutations refuse rather than pruning unresolved history. An unchanged or unavailable owner value remains unknown because it cannot prove an in-flight operation will never finish. Only the owning route’s documented pre-write coded refusals release a guard without completion readback.
