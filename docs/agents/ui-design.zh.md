# UI 设计规范

[English](ui-design.md)

这是 Web、桌面和原生 App 的共同设计规范，适用于所有新增、修改的界面及设计审查。平台指引规定组件选择，[UI 文案规范](ui-copy.md)规定措辞。既有页面在修改时遵循本规范；本文不代表已完成全产品改造。

**用布局、图标和交互表达，让界面本身告诉用户怎么用。Keep it simple。** 用户应能从结构和控件看出当前对象、状态和下一步。标签说明名称与动作，描述文字只补充界面无法清晰、安全表达的必要信息。

## 设计规则

1. **先设计结构，再补充说明。** 用层级、距离、留白和分组表达关系与重点。如果需要一段话解释该看哪里、该用哪个控件，先调整布局或控件。辅助描述按需出现，每行不必固定配一句说明。
2. **使用熟悉的组件和图标。** 遵循所在平台或应用外壳的组件规范。手机遵循[移动端设计](../../apps/mobile/DESIGN.md)的原生组件规则；Web 和桌面遵循 [DSH UI](../../.agents/skills/dsh-ui/SKILL.md)。图标帮助识别对象、动作和状态。不熟悉或影响重要的操作保留简短可见标签；纯图标操作必须有无障碍名称。含义不能仅靠颜色表达。
3. **让流程解释任务。** 将当前需要决定的事及相关信息放在一起，突出主要操作，立即回应输入，并就地显示进度、成功或可恢复的失败。确实需要先后决策时才分步，简单任务在同一处完成。
4. **按需展示细节。** 次要说明、背景和诊断信息放在名称明确的展开项或帮助入口中。当前决策需要的信息直接放在操作旁边。不能为了简洁而把必要指引或后果藏起来。
5. **保留必要文字与事实。** 简短标签、单位、当前值、权限范围、隐私边界、不可逆后果和可操作的错误信息仍需明确。安全核对必须在确认前展示完整必要值。简洁不意味着截断指纹、替用户决定或削弱知情同意。
6. **不同使用方式下都可操作。** 保留清晰阅读顺序、键盘与焦点操作、屏幕阅读器名称和可达按钮。大字号允许换行与滚动。明暗主题及维护的语言遵循同一信息层级，各平台使用自己的组件和外观。

## 示例

| 场景       | 由界面表达                                                   | 保留的文字                                                     |
| ---------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| 配对电脑   | 电脑身份、分组指纹卡片、聚焦的核对步骤，随后进入手机批准步骤 | 完整指纹、简短核对指引、明确的一致／取消操作；详细说明按需展开 |
| 选择设置   | 分组行、当前值及合适的开关、选择器或分段控件                 | 名称和值；只有控件无法表达的后果才加提示                       |
| 保存或重试 | 立即显示处理中，成功可见，失败在相关操作旁呈现               | 具体动作名称和简短恢复指引                                     |
| 授权或移除 | 确认位置展示对象与范围，主次操作明确                         | 权限范围、不可逆后果，以及含义明确的取消／确认标签             |

## 审查标准

每个改动流程都要检查：

- 不读大段说明，也能识别对象、当前状态与下一步。
- 每句描述都提供必要事实，交互本身由布局、控件和反馈表达。
- 次要细节可以按需查看，知情决策所需事实直接可见。
- 图标、标签与无障碍名称含义一致，信息不只依赖颜色。
- 在平台输入方式、大字号、明暗主题及维护的语言下可以完成任务。未验证的平台和无障碍模式单独记录。

按相应平台要求做运行验证，并提供 PR 证据。缩短一段说明或截一张漂亮图片，本身不能证明交互可用。
