# Conversation timeline

Reading a Bot DM or group: where the timeline opens, how it keeps your place, and how long messages and images display.

## Sub-features

- `static-avatars` keeps ordinary UI Bot portraits static in the timeline, Channels roster, headers, Group stacks and member/receipt surfaces. Generated portraits use SVG images instead of inline SVG descendants; Activity and attention remain independent static markers with truthful accessible labels. Still companions retain inline SVG head anchors; only explicitly enabled Window Companions retain their separate animation path.
- `memory-display` keeps the per-Bot elsewhere-memory visibility switch and adds Compact / Detailed in the existing action menu and Channel settings. Compact retains the Bot and origin, omits commit metadata and opens the same full diff on click. The preference is local to this browser; unset values stay Detailed.
- `new-messages` opens the Channel at the Human's read anchor and draws a `New messages` divider after it when someone else wrote since.
- `opening-selection` stops follow-up timeline requests and aborts in-flight initial read-position/timeline fetches when a Channel or Bot selection becomes obsolete. The cancellation subscription exists only while that opening is pending and is released on success, failure or cancellation; read mutations do not inherit its signal. An expired anchor falls back to latest only for the current opening; A → B → A must distinguish the two A openings by selection identity. Verify delayed original read-position and timeline requests in a foreground browser, switch away while each is pending, and check actual transport cancellation plus the final Channel and exact draft. Also release a non-cooperative late response and check that no obsolete timeline is requested or applied. Preserve active expired-anchor fallback and unread placement. Cached refresh and source-message lookup are separate paths; this does not establish their cancellation, Host SQL cancellation, or opening/scroll performance acceptance.
- `return-latest` shows an opaque icon-only return button above the composer at its right edge whenever the timeline is away from the latest messages; new live messages add a numeric badge. Hover and press change colour without transparency. It hides at the bottom and follows multiline composer height.
- `bidirectional-pages` opens a bounded window around the read anchor, then loads cursor pages at the top/bottom while preserving the reading anchor. Holding an edge must not start an unbounded loading loop.
- `bounded-host-hydration` keeps latest/older/newer/around page hydration proportional to the selected window rather than the total history. Cursor validation, future-version fallbacks, notice order, visible off-page reply/grant dependencies and metadata remain unchanged; Human visibility floors also apply to dependencies. This does not make the separate journal/write paths bounded or remove all SQL scanning for grant-resolution candidates.
- `sidebar-latest-preview` reads the latest non-notice message without hydrating each historical message. Keep reply previews, grant resolution, receipts, reactions, migrated attachments and forward-version fallback identical. For performance verification, compare the same ordinary three-Bot history and a large-history Channel on both builds, at least three runs each; distinguish sidebar request time from visible stable opening time. A notice-only suffix may still require scanning notices. Run `packages/core/test/channel-latest-message.test.ts` before the real foreground-browser journey; source tests do not establish the 1500ms opening or 120FPS gates.
- `keep-place` puts a Channel back at the message you were reading when you switch away and back within the same page.
- `fold` leaves messages expanded by default; with Auto-collapse long messages enabled, a settled message taller than 480px folds to 300px behind `Show all`.
- `message-time` shows each grouped message's own HH:mm next to its hover actions.
- `file-layout` keeps attachment names and sizes readable while Open and download controls wrap inside narrow message bubbles. Bubbles fit the larger of their prose and attachments; prose stays left-aligned with `text-wrap: pretty`.
- `image-preview` opens a thumbnail in an in-page preview that steps through every image loaded in the Channel.
- `reactions` adds the Human's emoji reaction from the hover bar picker, the long-press menu on narrow screens, or a chip under the bubble; Bots react through `bot_send_message` `react_to` + `reaction` (empty `body` for a reaction only); chips update live through `channel/reaction` and Bots read them in `channel_read`. The group avatar stays level with the bubble's bottom edge, not the chips.
- `search` opens with Ctrl/⌘+F, lists matches newest first and jumps to one with `openAround`.
- `member-mention` offers icon + label actions in the Channel sidebar member menu. Right-click, Shift+F10, and the member's ellipsis button all offer Mention, which appends one structured Bot mention to the current draft and focuses the composer without opening a DM.

## How to get to it (user POV)

- Open Bot settings → Messaging to enable Auto-collapse long messages. Long messages start expanded; when folding is enabled, Show all reveals the full body.

- In a Bot DM with Memory updates from another conversation, open its Channel menu → Show what this Bot did elsewhere → Memory display: Compact / Detailed. The same choice is under Channel settings → Show what this Bot did elsewhere → Memory display. Hide Memory updates to disable the choice; show them again to restore it.
- **Failed-turn report:** choose Report this error in a failed message. The Web/mobile feedback form preselects Bad and explains that POST adds only the matching turn input and tool calls/results, redacted and bounded. Preview first; synthetic upload tests must exclude unrelated turns, whole Sessions and diagnostic archives. Download remains separate.
- **Shared action state:** while a DM maintenance action is pending, open the context usage panel: both entry points observe the same lock and outcome, and competing compact/new clicks do not issue another request. Approval/question read retries retain their original request guards and do not replay decisions.
- **Session maintenance:** in a Bot DM Orchestrator failure card, choose Compact context or Start a new session directly. Buttons use icons and filled backgrounds distinct from the bubble. Neither action retries a message; verify the timeline count remains unchanged. No Retry or More recovery button remains. Groups expose neither maintenance action. Busy Bots refuse; failed compaction must not reset the Session. Repeat after Host restart to verify loading without a new Human message. The mobile app exposes the same actions (`session-compact`, `session-new`); submit native checks to the device queue.
- **Context occupancy:** the Web DM composer footer shows estimated current context / model capacity, marks a missing-capacity 200K estimate, and shows unknown occupancy for unloaded Sessions. Clicking opens current used/capacity/remaining/threshold/source details and cumulative usage. The chip has no approximation mark or text label. Only the Bot Human DM popover offers Compact context and Start a new session; neither retries. Groups expose neither action. Compare with `deepseekbot bot-context <bot>`; verify refresh after a turn and compaction, a model change, and a Bot switch. `/new` only retires the current Orchestrator and does not resend an old message.

- Enter Bot mode and open a DM that has messages after your last read position: the divider sits about a quarter down the view.
- Scroll up, open another conversation in the sidebar, then come back: the same message is at the same height.
- Send a file with a long name, then narrow the Messages dock panel: the file information and action controls stay inside both Human and Bot bubbles. Open the file menu and download the file.
- Click an image in a message: the preview opens; `←`/`→` or the side buttons step, `Esc` closes.
- Hover a message and click the smiley in its action bar, then pick an emoji; click the chip under the bubble to take it back. On a phone-width page, long-press the bubble and choose `Add reaction`.
- Press Ctrl/⌘+F in an open conversation, type a word, and press `Enter` or click a result.
- In a group Channel, open Members in the Channel sidebar. Right-click a Bot row (or use its ellipsis button / Shift+F10), then choose Mention (`@ TA` in Chinese).

## Driving it with verify-app

- **Bounded Host hydration (#3214).** Run `packages/core/test/channel-timeline-bounded.test.ts`, including history growth, full-history differential pages, sparse revisions/appends, cursor boundaries, Human visibility and off-page metadata. On identical actual Host data compare at least three latest/around/older/newer reads and three foreground Channel openings per build; record query/row counts separately from uninstrumented timing. Then drive unread-divider placement, older/newer edges, remembered reading position and repeat switching with exact canonical IDs. A bounded JSON response alone does not prove bounded Host work, and a source timing improvement does not prove browser/installed Desktop or 120FPS acceptance.

- **Companion reading space (#3214).** Record the actual selected Companion count before rapid A → B → C selection; owner readiness alone does not prove a Companion is selected. Distinguish an already-enabled Companion from first-browser onboarding that later initializes its default, and retain identical preferences on both builds. From the first stable readable/editable view, record the last message's screen position, timeline padding/scroll range, Companion selection changes and composer height, then focus and type without submitting. Check displacement from readiness as well as after input: extra diagnostic round trips can move a jump before the input-only probe is armed. Repeat at least three times per source build on identical data. Also check no-Companion and reduced-motion states, a real unread divider, a remembered history anchor, and enable/remove while reading. Unchanged composer height or a passing stylesheet test does not establish correctness; removing padding animation alone has failed the cold-onboarding browser reproduction. Keep diagnostic geometry measurements separate from low-overhead scroll timings.

- **Scrollbar activity (#3214).** Scroll a long Channel continuously: only the active surface's thumb stays visible, with no hide/show flicker or repeated inline-opacity removal/rewrite while already fully visible. Pause to observe the existing idle delay and fade; resume midway through fading and verify it stays visible for a fresh idle interval. Repeat in nested and sibling panels. Reduced motion hides without the fade; closing the owning Dock cancels pending scrollbar timers/frames and restores pre-existing inline values and priorities. Keep this lifecycle check separate from native-wheel frame timings and timeline anchor/gap checks; it does not itself prove 120FPS.

- **Portrait image identity.** Generated ordinary portraits must decode as full, nonblank images without inserting their SVG descendants into the document. In the avatar editor, change a pixel recipe, pose and line appearance; verify the preview updates and survives Save/reopen. Compare light/dark and narrow layouts. Export a conversation image containing these portraits and check the exported pixels, not only a successful download. Still and moving companions must retain their SVG head anchors. An image-backed implementation needs matched source-build performance evidence, not only a generated-bundle prototype.

- **Static avatars.** Open a Channel with several Bots and long history, switch repeatedly between it and another Channel, then scroll and inspect header/member portraits. Generated portraits must not blink, turn, morph into tool symbols or animate on entry, even while a Bot works. Check that activity labels and approval counts still update, Group stacks retain identity/overflow, and ordinary portraits have no running animations. Compare identical history fixtures at least three times per side with the timeline performance harness, keeping the unread-anchor journey below green. Unit resource assertions live in `packages/client/test/avatar-static.test.ts`; they do not replace browser or installed Desktop verification.

Preconditions: a model credential, a Bot with a few replies (one long list), three image attachments sent with `botharness/attachment/upload` and `rpc botharness/channelSend`, and `deepseekbot channel-mark-read <dm> --message-id <id>` on an earlier reply.

- **Memory display.** Use a task-owned Bot with an existing Group-caused Memory commit mirrored into its Human DM. Read `botharness/channelMessages` for that DM and keep the notice ID, SHA and origin Channel as canonical evidence. In the real Client, choose Compact from the Channel menu and verify only the icon, Bot, origin and update action remain; choose Detailed to restore the subject, SHA and file summary. In Channel settings choose Compact, close settings, refresh, hide/show Memory updates and switch away/back: the chosen style survives and the setting is disabled while hidden. Click the compact line and verify the diff SHA matches `botharness/memoryGitCommitDiff`; return to Chat. Capture both modes in light/dark, Chinese/English, narrow width and zoom with long Bot/origin names. Original Group notices and local DM commits keep Detailed. No model is required to render existing canonical notices.
- **Divider.** Open the DM; `[data-unread-divider]` exists right after the marked message, and `rpc botharness/channelReadPosition` returns that message before the visit.
- **Keep place.** Record `.bh-chat-body` `scrollTop`, open another DM, return; the value matches.
- **Reactions.** `deepseekbot channel-react <dm> --message-id <id> --emoji 👍` returns `reactions`, and an open page shows `[data-reaction="👍"]` without a reload; `--remove` takes it away and `deepseekbot bot-tool <bot> bot_send_message --args-stdin` with `{"channel_id","body":"","react_to","reaction"}` reacts as that Bot. In the page, `[data-reaction-picker-trigger]` opens `[data-reaction-picker]`; at 390px wide the long-press menu's `Add reaction` item opens it. A real Bot asked to acknowledge with ✅ calls `bot_send_message` with `react_to`, which `deepseekbot bot-trace` shows.
- **Search.** `deepseekbot channel-search <dm> --query <text>` lists matches newest first; in the page, Ctrl+F opens `[data-conversation-search]`, and `[data-search-result]` rows jump the timeline to their message.
- **Member mention.** In a group with a Bot member, type a draft, open that member's menu and choose Mention. Check that every action has an icon, `.bh-composer-rich-input [data-bot-id]` identifies the selected Bot, existing text remains and focus/caret are at the draft end. Repeat from the ellipsis and Shift+F10; a second Mention does not duplicate the chip. Send a uniquely marked message and read `botharness/channelMessages`: its Human message must retain the selected Bot's structured `mentions` metadata. No model is needed to verify insertion or submission; a reply requires one.
- **File layout.** Use a long-name text attachment in both a Human and a Bot message. Drag the Messages panel to 320px, 400px and 700px at a desktop viewport; repeat in light and dark themes. The filename has nonzero readable width, and `.bh-message-file` contains its Open and download controls without horizontal overflow. At wide widths, the bubble fits the text or attachment instead of stretching to the filename's uncapped intrinsic width; computed prose `text-wrap` is `pretty` and `text-align` is `left`. At 390px viewport width, repeat on the narrow layout. Open the file dropdown and download the original bytes. The compact Files panel remains a separate layout.
- **Fold preference.** Long messages are fully expanded by default, with no `[data-message-fold-toggle]`. Open Bot settings → Messaging; `Auto-collapse long messages` is off and searchable by its label. Enable it: settled long messages show `[data-message-fold="folded"]` and `Show all` expands them. Reload and verify the choice persists through the native `botharness-client` settings scope (`autoCollapseMessages: true`). Turn it off and verify the full body returns immediately and remains expanded after reload. Streaming output and interactive cards stay expanded with either choice. Repeat in light and dark themes. Select the switch by role as well as its accessible name: its surrounding SettingsRow group has the same name, so clicking that group does not toggle the switch.
- **Image preview.** Clicking a `.bh-message-image-link` opens `[role="dialog"]` named `Image preview: <file>`, with `2 / 3` style position text.

- **Return and large unread history.** Run `BH_E2E_INSTANCE=.humanlayer/verify/<name>/instance.json node scripts/e2e-timeline-navigation.mjs`. It seeds 260 messages using the real direct `bot_send_message` Bot tool (no model), marks message 120 read, and opens the 140-unread DM through the real Client. It records the canonical read position, opening around request, visible divider, older/newer cursor requests, one request per edge visit, idle no-loop intervals, retained prepend position, ordered unique rows, ordinary history return control, three live messages, bottom hiding, multiline draft without submission, actual light/dark appearance, and read-complete reopen. A second 150-message DM with 140 unread verifies that Return to latest loads the latest window when the newest message was outside the opening page. `BH_TIMELINE_BASELINE=1` expects the missing ordinary-history button and saves comparable before captures. `BH_SCREENSHOT_DIR` selects the evidence parent directory. The caller owns the Host; the journey closes its own browser in `finally`.

### Performance (#2413)

- **Visible60Hz scrolling (#3214).** Human priority is smooth scrolling on the current physical60Hz display; do not wait for120Hzhardware. Use foreground non-headless Chrome with normalVSync and real wheel/trackpad input through the production scrolling path, not DOM scroll-event dispatch. Keep immutable Group data, viewport, source identities and input distance/speed equal across at least three runs per side. Capture actual frame/presentation timing and dropped frames alongside renderer work, long tasks, input responsiveness, scroll anchors and gaps. A16.8msrAFp95 alone is not a no-dropped-frame pass; inspect outliers and the compositor/presentation evidence. The1500msguard catches catastrophic waits, not smoothness. Unlimited-frame-rate experiments, headless results and physical120Hzverification stay separately labelled. Installed Desktop and Human acceptance remain independent.

- **Cold Companion reading space (#3214).** With only the isolated test browser's local preferences cleared, switch from a long-history Group through two ordinary Groups while the initial onboarding receipt and roster refresh complete. Measure the visible message anchor from first readable/editable readiness, not only after text input. Also delay the real initial onboarding request until after that readiness and native text input, then release it unchanged: the reading anchor must not move or disappear. Record this gated transport diagnostic separately from ordinary opening timings; do not mock the receipt or move the readiness gate after default initialization. Recheck saved-empty and removed-Companion preferences without clearing a shared/normal browser Profile. Earlier initialization plus no-padding-animation passed five ordinary trials but failed three late-receipt trials with112px displacement; that source candidate was reverted. Browser, continuous-scroll, native Desktop and physical120Hz acceptance remain separate.

- **Native Sidebar subscription isolation (#3214).** Switch between ordinary Groups in the desktop workspace, then repeat with the native Sidebar visible in a narrower window. Channel selection and search stay live; Inbox badge/action updates and Inbox navigation still work. Count hidden native-slot and visible workspace Sidebar instances separately: CSS-hidden copies can still render. Conversation-only updates must not rerender the native navigation owner, while each Channel list retains its own subscriptions. `packages/client/test/bot-mode-sidebar.test.ts` guards repeated draft revisions and live badge/search/selection updates. A parent-render guard or a wide-window browser result does not replace narrow-window, unread/streaming or installed Desktop acceptance.

- **Streaming while reading history (#3214).** In a three-Bot Group with ordinary saved history, scroll away from the latest messages, then receive overlapping streaming replies. The reading anchor stays fixed with no visible gaps; settled message groups and their decision metadata do not rebuild merely because draft bodies grow. At the latest edge, all draft bodies still progress and settle into canonical messages. Toggle streaming off/on and switch away/back without stale drafts or lost composer text. Compare identical cumulative-draft replays at least three times per build, but label injected Client-state diagnostics separately from real model/Host transport verification. `packages/client/test/bot-main.test.ts` and `packages/client/test/content-redactions.test.ts` cover stable settled rendering and continued purge enforcement. Browser cadence is not physical 120Hz acceptance.

- `BH_E2E_INSTANCE=.humanlayer/verify/<name>/instance.json node scripts/perf-idle-timeline.mjs --messages 600 --profile` seeds a 600-message Group with mixed Markdown, mounts all of it and reports idle main-thread time and typing latency. Run it with and without `--animate`. Typing must not re-render the timeline: `typing.hottest` should not contain `MessageGroupView`. See [the performance guide](../references/performance.md).

## Gotchas

- **Expo Native Bot mentions (#2160).** Open a group with canonical `mentions` ranges (a Bot reply starting with `@nickname`, and a Human inline mention). The current avatar and primary-colored `@name` share the body text line. A leading mention joins the first supported Markdown paragraph; subsequent blocks keep the existing renderer. Tap the inline name and verify `/dm/<botSlug>` against the canonical ID, including after a rename. Missing IDs retain a readable stored label without navigation; unstructured `@name` stays plain text. Verify cached history, live and optimistic data through `apps/mobile/test/conversation.test.ts`; `apps/mobile/test/message-mentions.test.ts` covers ranges, identities, CRLF, references and streaming first paragraphs. Native checks: default/intermediate/maximum text × light/dark, inline wrapping, per-Bot name colors, long-press copy/reactions and keyboard draft retention. Follow the Human-confirmed inline-size exception in mobile DESIGN; do not restore a 44/48-point block height. The Human-selected presentation has no background: avatar + @ + primary-colored name, inline with body text. Record platforms separately; iOS remains unverified without its native lane. Bot mentions embedded later in Markdown retain Web's plain-Markdown behavior.

- Read positions only move forward. To see the divider again, post a new message so the Bot replies after the anchor.
- Headless Chromium reports `hover: none`, which hides hover-only times and shows the hover actions permanently. Launch it with `--blink-settings=primaryHoverType=2,availableHoverTypes=2,primaryPointerType=4,availablePointerTypes=4` to capture desktop hover states.
- `deepseekbot pause` and `resume` have no online adapter; you cannot pause a Bot on a live Host to keep it from answering seeded messages.

- The pinned DSH Menu renders one submenu level. Memory display choices are flat labelled rows inside the existing action submenu; do not encode a third menu level in MenuItem data. Settings uses the existing Select.


## Theme readability and quiet sending (#2875)

Use synthetic Chinese messages. Compare light/dark and custom yellow, green, white and black themes, including a custom panel background. Inspect Bot Markdown links, quoted text, code, Human text and settings actions. Send once with completion before 3 seconds: no visible delivery feedback. Delay another send beyond 3 seconds: feedback appears beside the unchanged bubble. Fail then retry: failure remains horizontally beside the bubble, retry starts a fresh delay, and no extra vertical status row appears. Record bubble and following-message positions before and after each transition. Compare multiple Web panels with different backgrounds. Native evidence follows the shared device lane; browser previews do not qualify native layout or accessibility.

### Android history failure recovery (#3257)

On the assigned Android Release phone, hold a numbered message at the oldest loaded boundary. Delay the older-page request, interrupt only the dedicated QA Host, then restore it. Record the same message ID and screen offset before failure and after reconnection (within 1 dp); the history Retry action must remain visible below the header. Press Retry without scrolling to reveal it: older messages appear above the same anchor, with no duplicate or missing IDs. Record transient frames separately from settled bounds. Repeat with keyboard, larger text, and a held message away from the top; verify latest-message following separately. Diagnostic delays/logs must remain outside production commits.
