# Native Bot creation, Marketplace, Git and Zip import

A Human creates a blank Bot on a chosen paired Host. The phone retains the exact creation operation before sending it; reconnecting recovers the original PersonaBot and Human DM.

Git import uses the same target, confirmation, operation record and completion path. A read-only source preview supplies an immutable commit before the submitted operation is saved. Recovery keeps that commit; if the remote branch advances before it can be imported, show the source-change refusal rather than silently selecting new content.

## Sub-features

- `target`: All explicitly chooses from every paired Host; a scoped Host is inherited. Changing the target preserves the draft and does not switch browsing.
- `form`: native name/persona fields, optional Bio/tags, validation and keyboard-safe submission.
- `android-page`: blank Bot and direct Git forms use full pages with native navigation Back, Settings-style grouped fields and Compose action buttons. Confirm actual keyboard/focus, text scaling and Back behavior; JavaScript adapter tests do not prove native rendering.
- `channel-page`: Android New Channel selects a Remote Host, name and multiple eligible Bots in a virtualized native-checkbox list. Changing Host immediately clears candidates and selection, retains the name, ignores late reads and never resurrects old selections. Submission retains the original pairing/input/key; a continuation notice survives leaving the form.
- `receipt`: the original Host, pairing identity, operation key and input survive app restart. Repeated taps and uncertain replies cannot create another Bot.
- `completion`: active progress opens the new DM on its Host; leaving progress retains the result in the creation flow without taking over navigation or adding a Home footer. Reenter through New to recover and open it.
- `refusal`: unsupported Hosts refuse before mutation; unavailable/revoked targets, changed input and archived results never fall back to another Host or fresh operation.
- `git`: a Git link, confirmed commit and editable name/Bio/tags produce one ordinary Bot with the imported personality; retry preserves its source, identity and DM.
- `marketplace`: browse the public catalogue before choosing a Host; native search, topics, details and README retain the selected listing and reviewed commit through confirmation. Android discovery uses a standard button group for sorting and borderless filter chips for topics. Check selected fill, unchanged repeat taps, actual result changes and the large-text radio-list alternative in light and dark themes.
- `zip`: retain the selected file, preview on the chosen Host, edit metadata and submit the same archive through bounded uploads. Recovery checks the original receipt before requiring file bytes.
- `statistics`: the existing mobile telemetry owner observes blank/Git/Zip/Marketplace preview, submit and recovery attempts; Host-confirmed creation, recovered completion, pending and uncertain transport stay distinct. The native and PostHog proof follows [the statistics handoff](../../../../docs/agents/mobile-bot-telemetry-qa.md); the optional Node wire test does not qualify the native path.

## How to get to it (user POV)

On the phone, open New from All or a selected Computer. Choose Create from scratch, Import Zip, Browse Marketplace or Import Git directly. Blank and direct Git use full pages with native Back navigation; Zip starts with the native file picker. Choose the Computer when needed, enter a name and persona, optionally expand more details, and create. Android also offers New Channel: choose the Computer before selecting participant Bots. For Git, Marketplace and Zip, choose the destination then tap Import once; source inspection runs inside that action. There is no separate Check button. Pending or completed creation remains reachable by reopening New after leaving the form, without a continuation footer below Home navigation.

## Driving it with verify-app

The existing CI journey `node scripts/e2e-personabot-create.mjs --with-dm` separately verifies the real Host lookup and built `create-status` CLI: absent lookup, same-input/key retry, one canonical Bot/DM and recovery after Host restart. Its four `blankCreation*` result flags do not establish native UI or injected network-fault acceptance.

The same journey uses a task-local Git fixture for CLI source preview, pinned import, discarded-reply readback, changed-source refusal and recovery after Host restart. Its `gitImport*` flags require an actual passing candidate run; adding the script does not establish that result. Paired-device gateway tests separately discard the accepted reply and verify revoked-device refusal.

`scripts/e2e-zip-import-proof.mjs` is an imported helper of that journey, not a standalone launcher. It exports a fixture Bot, uploads one chunk, restarts the Host, repeats the accepted chunk and finishes with the built CLI. It imports, discards the result, checks the original receipt, then restarts again and verifies the same Bot/DM and canonical counts. The `zipUploadAfterRestart`, `zipImportCliRecovery` and `zipImportAfterRestart` flags qualify only an actual passing run.

Use the designated [shared device QA runner](../../../../docs/agents/device-qa.md). This journey needs two isolated paired Hosts, no model, and a compatible native development build. Submit it to the Windows queue for Android; iOS has its own queue. Web screenshots do not qualify the native form.

1. Record the candidate and native-build SHA. Capture the previous creation entry on the compatible base before loading the candidate. Use synthetic Host names and redact addresses and pairing data.
2. Browse All → New → Create from scratch. Confirm the native pull-down (iOS) or M3 dropdown (Android) has no visible heading, all four source actions are directly visible in the stated order, outside-tap dismissal selects nothing, distinct Git/blank pages, and Zip opens the native picker with cancellation preserving the previous draft. Verify both paired Computers, including a fixture with identical display names, remain distinguishable. Confirm a target explicitly. Enter name/persona/Bio/tags, change A to B, and check the draft remains and browsing has not switched.
3. Submit twice rapidly. The active form opens the new DM on B. Read the Bot list and creation receipt through B's CLI; compare A before/after. Exactly one new identity and its original DM must exist on B and none on A. A new deliberate operation with the same name may create another identity.
4. Browse A and create again: A is already selected without another mandatory picker. Repeat with no model configured; creation still succeeds and the DM offers model setup without a test message.
5. Disconnect before submitting: retain the draft and require an explicit retry after reconnect. For a submitted operation, drop the create response after Host commitment using a task-local transport fixture. Restart the app, resume the retained operation and compare the receipt, Bot slug and DM with canonical Host state. Restart the owning Host and repeat recovery; there must be no second identity.
6. Leave progress before completion. Confirm the current page remains in place; use the completion action to open the same Bot on B. Repeat after app restart.
7. In task-owned fixtures only, revoke the paired device, unpair/re-pair it, archive the result, and change input under the same key. Each must show the appropriate refusal without creation on another Host. An old Host without the lookup method must receive no create mutation.
8. Check English and Chinese, light/dark, default/intermediate/maximum text size, real keyboard focus changes, multiline growth, accessible control names and reachable actions. Capture matched PNG/XML and the actual create/recovery interactions. Preserve the Human's settings, pairings and data.
9. Choose Git import with a task-owned fixture repository. Enter its link, edit name/Bio/tags, switch target before submission and verify every field remains. Confirm the source and create on B. Compare imported personality, ordinary identity and original DM through the Host CLI. Reopen after losing the accepted response; retry must preserve the same identity and pinned commit without a second Bot.
10. Advance the controlled Git fixture after source confirmation. A still-pending import must refuse changed source rather than use the new commit. A previously completed import must return its original result even if the repository is later unavailable. Record these as separate branches; do not change the saved operation to make recovery pass.
11. Open Browse Marketplace directly from New with no paired Host, then with paired Hosts offline and phone Internet reachable. Verify card banners/avatars/name/Bio/tags and matching social-profile detail, including missing/failed artwork and long names. On iOS, verify the floating untitled glass back/filter toolbar and native top scroll fade. Use the visible sort tabs and popular topic chips, then the full topic sheet; check the inset glass Close control and swipe dismissal. Open bottom-right search, type without fetching, submit with the keyboard or check button, repeat the same query to refresh, then close to clear. Verify keyboard reachability, default/intermediate/maximum text and light/dark. Search, sort and filter by topic; open details and follow a relative README link. Test empty results, failed refresh with cached content, a removed listing and catalogue identity mismatch. Failed or mismatched details must not enable import.
12. Choose Import from a listing. All requires a target; scoped A inherits A. Edit name/Bio/tags, switch to B, confirm and create through the Git journey. Repeat without pairing: retain the listing draft, pair, return and explicitly submit. After acknowledged completion, an explicit additional import creates a new operation; unresolved work cannot be replaced.
13. Refresh an outdated listing explicitly from confirmation, review the new source and return. Preserve edited metadata and target for the same draft. Fresh All browsing still requires a target choice. Verify virtualized search and topic selection with a real keyboard, maximum text, both themes and native Back/dismissal on each platform.
14. Choose a valid Bot Zip using the native picker before selecting a Host. Cancel the picker without losing the draft; select again and restart the app. Preview on A, edit name/Bio/tags, switch to B and verify preserved inputs and a new preview on B before submission. Exercise an invalid archive, an oversized archive and a temporary unreadable provider file.
15. Interrupt foreground upload after an accepted chunk and reopen. Verify acknowledged progress and identical file content, including after Host restart or staging expiry. Submit, discard the final response and recover the original operation and Bot/DM. A completed receipt must remain readable after staging expiry and local-file loss. For unresolved work, reselecting the original file requires its matching SHA-256 and size; a different file cannot replace the operation.
16. Leave progress or background the app while uploading/processing. The app must not promise continuous background upload or navigate from a hidden screen. Reopen explicitly and recover the same operation. Capture native file selection, target confirmation, upload, interruption and completion with matching CLI receipts; source tests do not replace these interactions.

Pair visible evidence with CLI `create-status` using the saved operation key and exact submitted input, canonical Bot/DM reads, and bounded redacted transport logs. Source tests cover deterministic lost-response and storage-failure branches; do not report those as native fault-injection results unless actually driven.

## Gotchas

- Android #2683: capture matched before/after blank and Git forms, plus the former channel-creation absence and the new full-page form. Drive light/dark and default/intermediate/maximum text with a real keyboard and TalkBack. Create a named channel with two Bots on A, then repeat after A → B → A: selections must reset at each different Host and the name must survive. Compare the returned Channel and exact members with CLI `group-create`/`channel <id>` readback on the selected Host; no other Host may receive the mutation. Protected Tob uses a Host-provided marker, never its display name or a fixed ID. Back before submission must create nothing. Drop a reply after acceptance, reopen and explicitly retry the same operation key; one canonical Channel must remain. Leave during submission: no background navigation, and Continue channel creation exposes the result. Keep native evidence and deterministic stale-response source tests separately identified.

- The operation key is bound to one Host and exact input. Never substitute a new key, pairing or target to make a failed journey pass.
- Before starting a mutation, lookup must establish recovery support. A missing method is a compatibility refusal, not a reason to call legacy create.
- Leaving the page does not cancel work already accepted by the Host.
- Record Android, iOS, CLI, injected transport faults and Human acceptance separately. Unrun cases remain untested.
